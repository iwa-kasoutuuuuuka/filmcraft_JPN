# 写真とナレーションの実録動画：作り方とノウハウ

状態: **まとめ**（2026-11-09）。イベントに参加した報告動画（写真のスライドショー＋ナレーション＋テロップ＋字幕、
1080p・5〜6 分）を、シナリオの文章と写真のフォルダから FilmCraft で作った記録。題材は利用者本人の YouTube の報告動画
（第8回 東北モトコンポミーティング）。作品の写真・音声はリポジトリに入れない。道具一式は作業フォルダ
`E:/filmcraft_JPN/TMT08/tools/` にある（リポジトリの外）。

ゲームのシナリオから 2D アニメを作る話は [text-to-video-knowhow.md](text-to-video-knowhow.md)。この文書はその仕組み
（`fcscript` の台本、`script.synthesize`、`anime.build`）を、立ち絵の無い実録動画に流用した結果をまとめる。

## 1. 全体像

```
シナリオ（文章）＋写真フォルダ
   │  ① storyboard.py     カット表を手で書く（写真・ナレーション・章見出し・テロップ・読み）。唯一の上流データ
   │  ② mosaic.py         顔・ナンバーにモザイク（mosaic_spec.json の枠）→ 画像_モザイク/
   │  ③ build_filmcraft.py 台本 *.fcscript.json・テロップ一覧・絵コンテ HTML
   │  ④ pass1_build.jsonl  script.synthesize（ナレーション合成）→ anime.build（写真＋ズーム＋字幕＋声）
   │  ⑤ place_telops.py   シーケンスのカット位置を読み、graphics.newText で編集できるテロップを置く
   ▼
TMT08.fcproj → filmcraft-cli export（H.264）
```

`make_filmcraft_project.py` が ②〜⑤ を順に走らせる。台本の文を直して再実行すると、変わった行だけ合成し直す
（`script.synthesize` は行の文と声の設定のハッシュで音声をキャッシュする）。**再実行は `.fcproj` を作り直すので、
FilmCraft 上で手で直した分は消える。** 直すのは常に storyboard.py の側。

| 段 | FilmCraft のコマンド・道具 | 主な設定 |
|---|---|---|
| 合成 | `script.synthesize` | `out`、`python`、`script`、`model`（外部の TTS をプロトコル経由で呼ぶ）、`ids`＋`force`（1 行だけ作り直す） |
| 組み立て | `anime.build` | `fps` 30、`sceneGap` 0.3、`pause` 0.35、`backgroundFit` fill、`push` 4（ゆっくりズーム）、`captionChars` 30、`voiceLufs` -16 |
| 検査 | `anime.check` | `out` に音声のフォルダを渡す（渡さないと全行「音声なし」の警告になる） |
| テロップ | `graphics.newText` → `graphics.set` | `track` は 0 始まり（0 = V1）。`time` は tick、`seconds` で長さ |
| 位置の読み取り | `filmcraft-cli --project p inspect sequence` | `video[0].items[].start / duration` がカットの位置 |
| 書き出し | `filmcraft-cli --project p export out.mp4 --format h264` | 6 分の 1080p30 で約 200 秒 |

## 2. ノウハウ（工程ごと）

### 2.1 過去の動画からフォーマットを取る

過去 3 本の構成（オープニング → 道中 → 会場 → メインイベント → 帰り道 → まとめ → ED）、区間の長さ、
定番の言い回し、テロップの位置と色をまとめてから、今回の写真に当てはめた。

- yt-dlp の字幕・情報の取得は、Windows では `PYTHONUTF8=1`（または `python -X utf8`）を付けないと日本語が化ける。
- 過去回は 4〜5 分半。今回は台本の文が多く、合成音声で 6〜6 分半になった（2.4）。尺を合わせたいなら文を削るのが一番効く。

### 2.2 Filmora 用のデータは諦め、FilmCraft で作った

最初は Filmora（16.1）で開けるプロジェクトを目指した。

- 自作の `.wfp`（zip）は「互換性がない」（エラー 600009）で開かなかった。無圧縮の zip にしても同じ。Filmora が書いた
  `.wfp` との差し替え実験では、`project_info` と中身のどちらを自作に替えても失敗し、原因を絞り切れなかった。
- **FCP7 XML（xmeml）は読み込めた。** メニューの「タイムライン XML をインポート」から読み、別のタイムラインのタブに入る。
- ただし XML 経由ではテロップを画像で渡すしかなく、文字を編集できない。利用者の要望は「文字を編集したい」だったので、
  FilmCraft のグラフィック（`graphics.newText`）で作り直した。**編集できる文字が要るなら、最初から FilmCraft で組む。**

### 2.3 カット表と絵コンテ

- storyboard.py に、カットごとに `photo`、`lines`（ナレーション＝字幕）、`chapter`（章見出し）、`telop`（下部テロップ）、
  `big`（画面中央の文字）を書く。シナリオに無い補足の文には `gen=True` を付け、絵コンテで灰色にして見分ける。
- 絵コンテ HTML（写真の縮小・開始時刻・秒数・ナレーション・テロップ）は、合成前に流れを確かめるのに役立った。
  秒数は**合成済みの WAV があればその長さ**、無ければ 1 秒 7 文字で見積もる。
- 合成音声の速さは 1 秒 約 5 文字（Qwen3-TTS の Ono_Anna）で、見積もりの 7 文字より遅かった。
  見積もりは短めに出ると思っておく。
- Python の `%` 書式で HTML を作るときは、CSS の `%` を `%%` にする（書き忘れると書式エラー）。

### 2.4 ナレーションの声

**結論: 標準語の女性ナレーションは Style-Bert-VITS2 の配布モデル `jvnv-F2-jp`。** Qwen3-TTS は読みは直せても、
訛りが直せなかった。

1. 最初は Qwen3-TTS の日本語女性プリセット `Ono_Anna`（指示なし）。誤読はルビで潰せた（下）が、利用者から
   「方言のようなナマリがある」と指摘された。Qwen3-TTS にはアクセント（音の高低）を指定する手段が無く、
   「標準語の正確なアクセントで」と指示すると誤読がかえって増える（[eve-burst-tts-quality.md](eve-burst-tts-quality.md)）。
2. Style-Bert-VITS2 JP-Extra はアクセントを辞書（pyopenjtalk）で付けるので、標準語に寄る。公式の配布モデルのうち女性の
   `jvnv-F1-jp` と `jvnv-F2-jp`（Hugging Face `litagin/style_bert_vits2_jvnv`、各 251 MB）を落とし、65 行を両方で合成して
   音声認識の検品にかけた。音素の誤り率は Qwen 0.020、F1 0.037、**F2 0.022**。F2 を採った。学習は要らない。
3. 呼び方: FilmCraft の外に置いた `filmcraft_sbv2.py`（TTS の JSON Lines プロトコルを話す）を、`script.synthesize` の
   `script`・`python`・`model`（モデルのフォルダ）で呼ぶ。65 行が 1 分ほど（Qwen は 1 行 10 秒）。
4. **クレジットが要る。** jvnv の学習データ（JVNV コーパス）は CC BY-SA 4.0。概要欄にモデル名・コーパス名・ライセンスを書く（2.8）。

声によらず効いたこと:

- **読みはルビで直す。** `READINGS`（語 → 仮名）を長い語から順に `｜語《よみ》` にして台本の `reading` に入れる。
  字幕は元の文のまま。英字（TMT、QR50、NS-1）、数字と単位（6度、7000円、6時間）、箇条の番号（「1、」→「いち、」）は
  最初から仮名にしておく。そのあと音声認識で聞き返し（`tools/eve_burst/tts_readings.py check`）、誤読した語だけ足す。
  Qwen では 3 回で誤読判定 7 → 1 → 0 行。
- ルビを読みに変えるのは `script.synthesize` だけ。`speech.synthesize`（1 本だけの合成）に `｜語《よみ》` を渡すと、
  語と読みの両方を読み上げる。試聴を作るときに注意。
- Style-Bert-VITS2 で検品に引っかかるのは、読みの誤りでなく滑舌の崩れ。**シードと速さ（`length` 1.0 / 1.08）を変えて
  4 通り作り、判定が 0 で誤り率の低いテイクを選ぶ**と、9 行中 7 行が直った。2 行（「捕獲」「段差」）は 8 通りでも残った。
- Qwen で短い 1 行（「お土産を買ったり、」）が止まらず意味のない音声を出し続けた。言い回しを変える
  （「お土産を買ったりして、」）と直った。
- Qwen で 1 行だけささやき声のように小さくなった（ピーク 0.08）。その行だけ `ids` と `force` で作り直すと直った。
- 声の大きさは `anime.build` の `voiceLufs` -16 でそろえる（指定しないと中央値 -28 LUFS だった）。書き出した動画は
  -13〜-14 LUFS で、YouTube の目安どおり。
- 他の GPU 処理（画像生成など）が動いていると、Qwen の合成が 1 行 100 秒ほどに落ちる（普段は 10 秒）。
- **台本の声の設定（`characters` の `voice`）を変えると全行のキャッシュが外れ、選んだテイクも上書きされる。**
  声は `script.synthesize` の `script`・`model` で替え、台本の側は触らない。

### 2.5 テロップ（編集できる文字）

- `anime.build` のあとで、`inspect sequence` から写真のカットの開始時刻と長さを読み、そこに `graphics.newText` を置く。
  カット番号で位置を決めるので、ナレーションの長さが変わっても追従する。
- トラックの割り当て: V1 写真、V2 章見出し・中央の文字、V3 下部テロップ。A1 ナレーション、A2 BGM、A3 効果音。
  `anime.build` が作る不要な V4 は消す。
- 見た目: 章見出しは左上 [90,170]、96 px、黄色の文字に紺の帯。下部テロップは左下（行数に応じて上へずらす）、64 px、白。
  中央の文字は 104 px。どれも Yu Gothic Bold、黒の縁取り、紺の背景（不透明度 85）。
- 置き直すときは、テロップが既に置かれていたら止める（二重に置かない）。やり直しは組み立て（pass1）から。

### 2.6 顔とナンバーのモザイク

- 「人の顔と車」を隠す依頼を、**顔とナンバープレート**と解釈した。車ごと隠すと、駐車場の写真がほぼ全面モザイクになるため。
  車ごと隠す枠（`car`）も書けるようにしてある。
- 自動検出は使えなかった。この PC の OpenCV 5 には Haar の顔検出（`CascadeClassifier`）が無い。代わりに、写真ごとに
  1 割刻みの格子を描いた縮小画像を作り、**目で見て枠を書いた**（38 枚中 10 枚、顔 34・ナンバー 23）。
  `mosaic.py --check` で枠の周りを拡大した確認図を作り、ずれた 3 か所を直した。横顔や帽子の顔は、検出器より目のほうが確実だった。
- モザイクは写真のコピーに焼き込む。FilmCraft には `clip.censor`（モザイク・ぼかし、楕円・矩形、追跡あり）があるが、
  写真にズームの動きを付けているので、枠がずれる心配がある。コピーなら動きに関係なく隠れる。
- ブロックが小さいと、モザイクでなくぼかしに見え、ナンバーの形も残る。ブロックは枠の短い辺の 1/4.5（最低 8 px）にした。
  「もじゃもじゃ」の縁は、楕円の半径に波と細かいギザギザを足して作る。
- 最後に、書き出した動画からコマを抜いて（ffmpeg は確認用の外部ツールとしてだけ使う）、隠れていることを確かめた。

### 2.7 書き出しと確認

- 全編の下書きは約 1 GB。人に送るときは冒頭 40 秒を 720p に縮めた試聴版（約 4 MB）にする。
- 音量は ffmpeg の `ebur128` で測る（-14 LUFS 前後が目安）。
- Windows の Git Bash で Python の出力を `while read` で回すと、行末の `\r` が残って ffmpeg の `-ss` がエラーになる。
  値を直接書くか、`tr -d '\r'` を挟む。

### 2.8 公開（概要欄）

- 概要欄に、本文・チャプター・クレジット・ハッシュタグを書いた（作業フォルダの `台本・構成/04_YouTube概要欄.txt`）。
- チャプターの時刻は、カット表から計算した各章の開始時刻。YouTube の条件は「0:00 から始まる」「3 つ以上」「それぞれ 10 秒以上」。
- クレジット: 「ナレーション音声：Style-Bert-VITS2（音声モデル jvnv-F2-jp）」、Hugging Face のモデルの URL、
  「学習データ：JVNV コーパス CC BY-SA 4.0」、コーパスの URL。合成音声であること、モザイクをかけたことも一文ずつ書いた。
  BGM・効果音を足したら、その素材のクレジットも足す。

## 3. 未解決の課題と次の手

- 新しい声（jvnv-F2）のイントネーションが自然かどうかは、まだ利用者が耳で確かめていない。自動では測れない
  （[eve-burst-tts-quality.md](eve-burst-tts-quality.md) 8 章）。
- 「捕獲」「段差」の 2 行は聞き取りに崩れが残る。言い回しを変えるか、その行だけ録音に差し替える（`voiceFile`）。
- 顔とナンバーの枠は手作業。FilmCraft には顔検出（`crates/render/src/facedet.rs`、Haar のカスケードを同梱）があるので、
  写真の顔の枠を返すコマンドとして出せば、目で見る作業を確認だけにできる。ナンバーの検出は未着手。
- 冒頭の「岩です」も女性の声で読んでいる。本人の録音に差し替えるかは利用者の判断。
- BGM は未設定（A2 は空）。

## 4. 次回（別の回）に流用する手順

1. 作業フォルダをコピーし、`画像/` を入れ替える。
2. storyboard.py をシナリオから書き直す（カットごとの写真と文、章見出し、テロップ）。英数字と数字の読みを `READINGS` に足す。
3. `python mosaic.py` の前に、写真を格子つきで見て `mosaic_spec.json` に顔とナンバーの枠を書き、`--check` で確かめる。
4. `python make_filmcraft_project.py` で組む。`anime.check`（`out` つき）でエラーと警告が 0 か見る。
5. `tts_readings.py check` で読みを検品し、誤読はルビ、滑舌の崩れはシードと速さを変えて作り直す。
6. 書き出して試聴版を作り、耳で確かめる。概要欄のチャプターを付け直す。
