## 1. 全体像

台本（JSON、プロジェクトの外）を**唯一の上流データ**にする。下流の素材とクリップはすべて台本の行 id で
追跡するので、台本を直したら、変わった行だけをやり直せる。人が見るのは最後の 1 回だけ。

```
文字（小説 / ゲームのシナリオ）
   │  ① 台本化   変換器（外部スクリプト）または LLM が *.fcscript.json を書く
   ▼
台本（行 id・話者・表情・場面・順路）
   │  ② 順路と話数   when / requires / route、merge_routes、episode_plan
   │  ③ 脚色（圧縮）  adapt.py、check_adaptation.py（LLM を話ごとに並列）
   ▼
話ごとの台本
   │  ④ 検証        script.validate
   │  ⑤ 声の割当    script.pickVoices / voice_refs.py / extras_voices.py / apply_voices.py
   │               感情ラベル（emotion_labels.py）と感情別の参照（voice_styles.py → voice.styles）
   │  ⑥ 合成        script.synthesize（差分・キャッシュ）  ← GPU 直列
   │               → 読みの検品 tts_readings.py（check → apply → 再合成、最大 3 周）
   │  ⑦ 口パク解析  script.lipsync（音量包絡）
   │  ⑧ 立ち絵差分  mouth_cutouts.py → sprite_variants.py（台本に結び付ける）
   ▼
   │  ⑨ 組み立て    anime.build（Tick 精度、1 回の取り消しで戻る）
   │  ⑩ 検査        anime.check
   │  ⑪ 書き出し    export（anime.run が通しで呼ぶ）
   ▼
人が観る → 台本か設定を直して ④ 以降を再実行（変えた行だけ）
```

`anime.run` が ④ → ⑤（任意）→ ⑥ → ⑨ → ⑩ → ⑪ を 1 回で通す。⑦ の口パク解析は ⑨ の中で使われる。
その前の ①〜③ と ⑧、および感情ラベルと読みの検品は外部の道具で、FilmCraft 本体には入れていない（タイトルごとに違うため）。
**1 話分の ⑤〜⑪（と素材の流し込み）を段階ごとの成果物つきで通す外側の道具が `episode_run.py`** で、
全 30 話はこれで回した（3.9）。

## 2. 機能一覧

### 2.1 台本の形式

`*.fcscript.json`（version 1）は、プロジェクトの外の独立した JSON。要点だけ書く（全項目は
[script.md](script.md)「Format」）。

- **characters**: `name`、`voice`（`refAudio` + `refText` でクローン、または `speaker` + `instruct` でプリセット。
  `styles` に感情ラベル別の参照を持たせると、行の `instruct` がそのラベルで始まるとき、その参照でクローンする）、
  `expressions`（表情名 → `image`、`openImage`、`vowelImages`（あ・い・う・え・お）、`blink`）、`defaultExpression`。
- **scenes**: `id`、`title`、`pov`、`when`（時系列に並ぶ文字列）、`requires`（先に見せる場面）、`background`、`bgm`、
  `transition`（`cut` / `fade`）、`hideCharacters`、`lines`。
- **lines**: `id`（全体で一意。音声ファイル名になる）、`kind`（dialogue / narration / monologue / direction）、
  `speaker`、`text`（話す内容かつ字幕。青空文庫のルビ記法を読みとして使う）、`reading`（話すときだけ置き換える仮名）、
  `expression`、`voiceFile`（既存の録音。ある行は合成しない）、`instruct`、`sfx`、`pauseAfter`、
  `generated`（ツールが足した行）、`spoken: false`（字幕だけで声を作らない擬音）、`video`、`subCg` / `subCgAnchor`、
  `slot`（1 左、2 中央、3 右）。
- **route**: 場面 id を見せる順に並べる。台本に無い場面は表示されない。
- 上限（1 行 4 000 文字、場面 1 万、行 20 万、ファイル 64 MB）を超える入力は敵対的なものとして拒否する。

### 2.2 コマンド

| 系統 | コマンド | 何をするか |
|---|---|---|
| `script.*` | `script.validate` | 台本の検査。エラー（id の重複、前提の順序、範囲外の `slot` など）と警告（時間の逆行、声が無い話者など）、統計（録音のある行 / 合成する行の数） |
| | `script.pickVoices` | 録音のある行の中から、キャラクターごとの参照クリップを選ぶ（2.5〜12 秒、6 秒に近い、落ち着いた行、話速が妥当）。`write` で台本に書く |
| | `script.synthesize` | 録音のない話す行を、キャラクターの声で `<out>/<id>.wav` に合成する。行ごとのハッシュを `manifest.json` に残し、2 回目以降は変えた行だけ。400 行ごとに保存するので、途中で落ちても続きから |
| | `script.lipsync` | 台本の全行について、口の開閉の時刻を `lipsync.json` に書く |
| `lipsync.*` | `lipsync.analyze` | 1 つの音声ファイルの開閉（`three: true` で半開きを足す）。音量包絡だけで決め、モデルは使わない |
| `speech.*` | `speech.synthesize` | 行のリストまたは 1 文を WAV とメディア項目にする。参照音声、プリセット、`instruct`、言語、モデル、デバイスを指定できる |
| | `speech.synthesizer` | 何が合成するか（Python と `filmcraft_tts.py` の場所、`--probe` の結果）を返す |
| `anime.*` | `anime.build` | 台本を新しいシーケンスに並べる（下表）。1 回の取り消しで戻る |
| | `anime.check` | 並べた結果の自動検査 |
| | `anime.run` | 検証 → 参照選択（任意）→ 合成 → 組み立て → 検査 → 書き出し（任意）を、最初に失敗した工程で止まりながら通す |

`anime.build` が作るトラック（詳細は [script.md](script.md)）:

| トラック | 内容 |
|---|---|
| V1 | 背景（場面ごとに 1 枚、ゆっくり寄る）。行の `video` がある間はそのムービー。`transition: fade` は黒からのフェードイン |
| V2 / V3 / V4 | 話者の立ち絵 / 口の差分（声が出ている間、母音ごと）/ 瞬き |
| V5〜V10 | `slot` 1・3 のときの左右の立ち絵と、それぞれの口・瞬き（2 ショット） |
| 最上段 | サブ CG（小窓） |
| A1 / A2 / A3 | 声（音量を揃える）/ BGM（場面の長さまで繰り返し、`bgmGainDb` −18）/ 効果音（声より 10 LU 下に揃える） |
| 字幕 | ルビを除いた平文を、文末・読点で切って長さに比例して配分 |

時間はすべて Tick（1 秒 = 254 016 000 000）で、行の長さは「音声の長さ＋間」、境界はフレームに乗る。

`anime.check` の種類: `offline`（素材がない）、`gap`（背景の穴）、`overlap`（声の重なり）は**エラー**。
`silence`、`loudness`（声の中央値から 6 LU 超）、`effect-loud`（効果音が声の中央値の 6 LU 以内）、字幕の
`caption-long` / `caption-fast` / `caption-short`、`no-audio`、`empty`、`no-voice` は警告。

### 2.3 台本の外の道具（Python、標準ライブラリのみ。例外は TTS 側）

`eve_to_script.py`（変換）、`merge_routes.py`（2 視点を日ごとに交互に並べる）、`episode_plan.py`（話数に切る）、
`adapt.py` と `check_adaptation.py`（脚色と機械検査）、`assets.py`（素材の名前解決）、`voice_refs.py`
（声の棚卸しと参照の選定）、`apply_voices.py`、`extras_voices.py`（エキストラの声を役名で固定）、
`protagonist_sprites.py`、`mouth_cutouts.py`、`sprite_variants.py`、`onomatopoeia.py`、
`emotion_labels.py`、`voice_styles.py`、`tts_readings.py`、`episode_run.py`、

## 3. ノウハウ（工程ごと）

各項目は「何が起きたか → どう直したか → 規則」の順に書く。

### 3.1 台本化と分岐の順路

**分岐ゲームは命令列を解釈して 1 本道にする。** 文字を拾うだけでは足りない。フラグ、条件分岐、メニュー、
シナリオ間の移動を実際に実行し、選択肢を方針（policy）で選ぶ。ゲームに固有の部分なので、小説には要らない。

- **何が起きたか（往復で道がふさがる）。** 最初の方針（`explore`: 先読みして新しい内容がある選択肢を選び、
  行き詰まったらテレポート）は、日付順を通らなかった。小次郎編で日付ムービー 3 本（12/4〜12/6）が一度も再生されず、
  別の 1 本が 4 回再生され、2 つの場所が互いを指す往復が約 60 回続いて道がふさがった。12/3 が 9 616 行になった。
  **直し:** `days` 方針（既定）。①後の日に進む選択肢は最後に回す、②「次のメニューまでに新しいものがある」
  行き先を先に取る（往復の原因だった「先にあるものの合計」で選ぶのをやめる）、③行き詰まったら、メニュー選択だけで
  行ける最寄りの新しい場所を幅優先で探して歩く、④過去の日付ムービーをもう一度出す行き先は最後。
  **規則:** 探索は「その日に新しいものが残っている間は次の日に進まない」にする。テレポートは道が無いときだけ。
- **何が起きたか（共有フラグ）。** 両主人公は F0〜F255 を共有し、相手側でしか立たないフラグがある
  （一方の 12/4 の学校は、他方の側が立てるフラグを待つ）。一方の側だけを実行すると進めない。
  **直し:** **ザッピング**。もう一方の側を同じフラグで裏で進め（台本には書かない）、主の側が次の日に進む前と
  行き詰まったときに相手側を主の日の終わりまで進める。12/6 の 2 つの端末のように、互いにフラグを渡し合う箇所では、
  相手側がまず待つ（主の側がフラグを変えたときだけ数える）。合流場面（2 つの側が出会う）の手前で相手側は止まり、
  主の側が行き場を失ったら合流する。
  **規則:** 共有状態のある複数視点は、実際に切り替えて遊ぶのと同じ順で動かす。
- **何が起きたか（キーパッド）。** 数字キーを順に押して場所に戻るメニューは、場所だけで状態を区別する探索では見つからない。
  **直し:** 場所だけで見つからないときに限り、途中で変わったフラグも状態に含めて探し直す（最初からフラグ込みで探すと
  別の行き止まりができて、日付ムービーを飛ばした）。
  **規則:** 状態の区別は粗いほうから始め、見つからないときだけ細かくする。
- **結果。** 両編ともテレポート 0、日付ムービーは各 1 回で順番どおり。小次郎編 30 077 行（日ごとの最大は 12/7 の 7 520 行、
  のちに船の部分を直して 12/6 が 8 907 行、12/7 が 3 844 行）。両編を日単位で交互に並べると 2 709 場面・53 278 行
  （順路修正の途中では 2 728 場面・52 707 行）。
- **規則（安全）。** 変換は命令数・行数・移動数・各命令の訪問数・選択肢ごとの繰り返しに上限を持ち、敵対的または
  ループするシナリオは理由を付けて終わらせる。1 回の変換は約 10 秒。

**`when` と `requires` を必ず書く。** 変換器は最初、視点（`pov`）だけで `when` / `requires` を書かず、
2 つの視点を並べても `script.validate` が時系列と前提を見られなかった。日付画面と日付ムービーの出現で日を進め、
`D03-0012` のように「日＋場面番号」で書く。両視点が合流する場面は反対側の最後の場面を `requires` にする。
`merge_routes.py` が日ごとに A → B と並べ、`requires` を満たす順に直し、id に接頭辞を付ける（音声ファイル名は
id なので、合成も別名になる）。
**規則:** 台本を作る側が時間と前提を書き、検査は `script.validate` に任せる。

**1 話の長さで切る。** 日単位で切ると 1 話が数時間になる（12/3 の小次郎編 5 876 行 × 約 2.65 秒 ≒ 4 時間 20 分）。
`--episode-lines 600` で場面の境目で切ると 1 話約 26 分。**規則:** 1 行の平均は声＋間で約 2.65 秒。話数は行数上限で決め、
場面は切らない。

### 3.2 話数と脚色（圧縮）

**何が起きたか。** 無編集で並べると、両編 52 707 行で約 39 時間（テレポート解消前の見積り）。解消後は 53 278 行で
見積り 43.8 時間、繰り返し部分を削って 36.3 時間（`episode_plan.py` の機械的な削り: 3 行以上続く既出の会話、
点だけの録音なし行、空になった場面）。利用者の決定は 1 話 24〜30 分、全体で 28〜30 話、最終話は 1 時間程度。

**直し。** `episode_plan.py` が 29 話（27 分 × 28 話＋最終話 60 分）の下書きを作る（全体で約 37〜39 % を残す）。
各話を LLM セッションが 1 話ずつ並列に脚色し、`adapt.py` の編集リスト（delete / rewrite / merge / insert / reading /
pause）を適用し、`check_adaptation.py` と `script.validate` で機械的に合格判定する。話と話のつなぎは、日ごとに
別のセッションが読んで、前の話で削った行を後の話が前提にしていないかを確かめ、編集リストの側で直した。
最終的に 30 話・約 14.5 時間（各話 26.5〜29.0 分、最終話 62.9 分）で全部合格。ただしこの脚色済みの 30 話は、
順路修正（テレポート解消）の**前**の順路から作ったもので、現行の順路からは作り直していない（4.2 の K）。
この脚色版を全話書き出しの入力にしたが、番号を振り直した後の古い複製が混じって 1 話ずれた（3.9）。

**規則（脚色）。**

1. **録音のある行は削除だけ。** `text`、`speaker`、`kind`、`voiceFile` を変えない（録音と合わなくなる）。`reading` の追加は可。
2. 録音のない行（主人公の台詞の大半と語り）は、筋を変えない範囲で書き換え・統合してよい。書き換えた行は id を保ち
   `generated: true`。統合は最初の行の id を残す。
3. 新しい行（ブリッジ）は新しい id（`<場面>-g01`）、`generated: true`、録音なし。
4. 順序は入れ替えない。場面は削れるが足せない。
5. 脚色が足してよいもの: 間（`pauseAfter`）、効果音、表情、読み、`direction`。
6. 合格判定は機械でやる（規則違反と尺。終了コード 0 / 1 / 2）。例外は 2 つだけ（録音を台詞の代わりに鳴らす `voiceOnly`、
   番号付きの端役を別の登場人物に付け替える `speaker`）。
7. 人が読むのは最後だけ。脚色の指示は「台本ファイルと形式と規則」だけを渡す。コードではなく内容の仕事。

**ゲームの間（ま）の情報は落ちる。** 選択肢、ハッキング画面、地図、フェード、声の停止は変換で無視される。
**規則:** これは道具の問題ではなく演出の問題なので、脚色でト書き（`direction` の `sfx`・`pauseAfter`）を足して補う。

### 3.3 声

#### 参照クリップの選び方

**何が起きたか。** 主人公 2 人は、自分のルートでは台詞が文字だけで録音がない（全 52 033 行のうち録音のある行は
16 159 行、31.1 %。未収録 35 874 行のうち、この 2 人の分が約 32 700 行）。声は、脇役として登場する別ルートの録音から
クローンするしかない。自動選定の第 1 候補（4.5 秒の参照）で合成した小次郎は、参照が問いかけで語尾の上がる調子だったため、
心の声まで高く明るくなった（基本周波数 F0 は参照が 148 Hz、合成が 150〜187 Hz）。
**直し。** 落ち着いた言い切りの 2 本をつないだ 11.9 秒の参照に替えると 103〜115 Hz になった。台詞・心の声・語りのすべてに
同じ参照を使い、全話の台本も差し替えた。
**規則。**

- **参照クリップの調子が、合成全体の調子を決める。** クローンは `instruct` に従わず、録音に従う。
  話す相手に向かう録音は、独白に使うと外向きになる。
- 聴く前に、基本周波数（自己相関）で確かめる。声の窓の目安は男声 60〜160 Hz、女声 165〜300 Hz、
  子供 200〜450 Hz（`extras_voices.py` の採用基準）。
- 参照は 4〜12 秒の落ち着いた全文（`！` や感嘆詞、笑い・叫び、ほぼ点だけの行は避ける）。1 本で足りなければ、
  同じ話者の落ち着いた 2 本をつなぐ。自動の選定（`voice_refs.py`）は、文面の調子 40 点を含む 100 点満点で採点するが、
  音声側に調子のラベルは無いので、最後は F0 と耳で決める。
- 参照の `refText` を付ける（付けないと話者埋め込みだけで、クローンの質が下がる）。声の権利と同意に注意
  （[text-to-speech.md](text-to-speech.md)）。
- **`refText` は録音と一字一句そろえる。** 台詞の対応表には、録音に入っていない文が混じることがある。小次郎の参照
  （2 本をつないだ 11.9 秒）の `refText` の先頭に、録音にない 1 文が入っていた。直すと、比較 20 行の誤読語の残りが
  80 % → 77 %、第 1 話を合成し直した初回の誤読行が 34 → 16 になった（読みへの効果は小さいが、原理的に正しく費用はゼロ）。
  台本 57 本・104 か所を直した。`tts_readings.py refs` が、全参照（54 本）の録音と `refText` の照合を 3 分で行う。
  **規則:** 参照も、学習データも、使う前に録音と文字を照合する。`voice_refs.py` で作り直すと元に戻るので、作り直す前に照合を入れる。

#### 設計してからクローン

**何が起きたか。** 日本語の男性プリセットが Qwen3-TTS に無い。男性の端役（守衛・警備員・フロント・警官など、約 1 100 行）に
声が要る。VoiceDesign（文章で声を作る）に「低い声の男性」と指示すると、守衛は F0 86 Hz の男声になったが、
「やや高めの声」と書いたフロントは 211 Hz、「しゃがれた低い声」と書いた警官は 235 Hz（94〜308 Hz で不安定）、
クローン後は 273 Hz と、**女声域に飛んだ**。
**直し・規則。**

- 1 文を VoiceDesign で作り、その WAV を参照にして Base モデルでクローンする（"design, then clone"）。
  設計した声は 1 行ごとに少し変わるので、**1 回作って固定**する。同じ指示でもう 1 文作った例は 86 Hz のまま、
  クローンした 2 行は 85 / 87 Hz で、声は保たれた。
- 指示文は「低い声の男性」を明示し、「高め」「しゃがれ」の修飾は避ける。役ごとに 2〜3 回作り、F0 が窓に入るものを採り、
  最後に必ず聴く。F0 は聴感の代わりにならない（実際、新しく設計した 10 本は 2026-11-06 に利用者が聴いて承認している）。
- 台本側は `refAudio` / `refText` のままなので、FilmCraft 本体は変えなくてよい。

#### 役名で声を固定する

**何が起きたか。** 変換器は話ごとに無名の話者へ `n001`… と振り直すので、同じ守衛が話ごとに違う id になり、
id で声を決めると話ごとに声が変わる。
**直し。** `extras_voices.py` は**表示名**で声の種類（クラス）と参照を引く。78 の役名に 13 の声を割り当て、
同じ場面で話す 2 人が声を共有しないよう、行数の少ないほうを同じ性別の別の声に移す（大きな役は動かさず、
動かしたくない小役は声を固定できる）。
**規則:** 声は id ではなく役名に結び付け、表は台本の外に置く（再実行で既存の編集を保つ）。

#### 読みの誤りと検品（音読み・訓読み）

**何が起きたか。** 第 1 話の最初の版を観た利用者の評価は「漢字の音読み・訓読みの誤りとイントネーションがひどい」。
Qwen3-TTS は漢字を自分で読み、読みの辞書を持たない。測ると、第 1 話の合成 296 行のうち 34 行（11 %）に誤読があった
（声優の録音を同じ方法で測った基準線は 10 %、これは認識器側の誤りで、合成の誤りではない）。誤読は特定の語に集中し、
**音読みの熟語（漢字 2 字以上）が 6 割強**、残りは訓読みの活用形と 1 字の名詞。同じ 20 行を別のシードで 3 回合成しても、
誤読語の 74〜80 % が毎回同じ誤りになる。ガチャではなく、モデルがその語の読みを知らない。
**効かなかったもの。** 参照の長さ、x-vector だけにする、温度を下げる、`instruct` で「標準語のアクセントで」と頼む
（むしろ悪化）。設定では誤読語の 6〜8 割が残る。
**直し。** テキスト側で読みを渡す。①名前は辞書（`eve_names.json`）でルビにする。②合成した音を 2 つの認識器（日本語特化の
Whisper と、音素を直接書き取る CTC 認識器）で聞き返し、**両方が同じ漢字語で食い違ったときだけ**誤読とみなす
（漢字で書き起こす Whisper だけでは、誤読しても同じ漢字で書かれて見えない）。③その語だけを `｜語《かな》` にして
`reading` に入れ、その行だけ合成し直す。これを最大 3 周する（`tts_readings.py` の check → apply → `script.synthesize`）。
**結果。** 第 1 話は誤読のある行が 34 → 5 → 1、参照の `refText` を直して合成し直した版では 16 → 4 → 0。比較 20 行では、
かなを入れた案はどれも誤読語の残りが 14〜16 % まで下がり、残りの多くは認識器の誤検出（実際の誤読はほぼ 0）。
全文をかなにしても読みの正しさは選択的ルビとほぼ同じ（イントネーションは耳で判断）。
**規則。**

- 読みは設定ではなくテキストで直す。**検品で誤読と判定された語だけ**をかなにする（開く語が最も少なく、効果は全文かなと同じ）。
  ひらがなとカタカナで差は無い。名前はカタカナ、その他はひらがなでよい。
- 検品は音で確かめる。LLM に書き換えさせる方法も同じ精度が出るが、誤読語の知識が要り、GPU を TTS と取り合う。
- 認識器の前後に 0.4 秒の無音を足す（足さないと短いクリップの冒頭を取りこぼし、誤り率が 4 倍に見える）。
- 認識器の誤検出はある（声優の録音で 1 割）。害は小さい（その語がかなで読まれるだけ）。両方が同じ誤りを聞き間違えると見逃す。
- 算用数字は解析器が漢数字で返すので本文に語が見つからない。誤読の判定が漢数字なら、数字の並びを丸ごとルビにする。
  助数詞の音便（10本→じゅっぽん）は道具では扱わず、台本の `reading` で直す。
- まとめ合成（複数行を 1 回で作る）は Qwen では危険。静かな参照でまとめて作ったら、後半 3 行がほとんど読み飛ばされた。
  まとめ合成を使うなら、切り分けた各行の音素誤り率で読み飛ばしを自動検出する。
- バッチ合成は、止まらない行が 1 本あるとバッチ全体が上限まで生成し続ける。`max_new_tokens` を文の長さから決める
  （12 フレーム/秒 ×（3 秒＋文字数/3）を上限にして解決した）。短い 1 行が止まらないときは、言い回しを少し変えると直る。

#### 棒読みと声の演技（感情別の参照）

**何が起きたか。** 読みを直した版（Style-Bert-VITS2 を試した版を含む）を観て、利用者は「棒読み感がある」と評価した。
クローンは録音の調子に従うので、1 本の落ち着いた参照では全行が落ち着く（前述）。
**直し。** 行ごとに感情ラベルを付け、ラベルごとの参照でクローンする（**B1**）。ラベル（普通・怒り・驚き・問い・呆れ・喜び・
甘え・動揺・静か、強さ 弱・中・強）は `instruct` に `怒り（強）` の形で書く。`emotion_labels.py` が、表情番号と文面の記号
（独白の括弧、`！！`、`！？`、`？`、`‥‥`、笑い）から付ける。`voice_styles.py pick` が声のあるキャラ（18 人・83 種）の
ラベル別の参照を、4〜12 秒で録音が台詞どおりのものから選ぶ（4 秒以上の録音がなければ短い 2〜3 本をつなぐ）。
FilmCraft 側は `voice.styles` と、行の `instruct` のラベルで参照を選ぶ処理（`怒りっぽく` は `怒り` を選ばない、
最長一致）を足した。キャッシュの鍵は実際に使う参照で計算するので、ラベルの無い行のキャッシュは生きる。
**結果（小次郎 12 行 × 2 シードと茜 8 行）。** 怒り・驚きの行と静かな行の差が、声の高さで 35 Hz → 52 Hz、音量で
1.3 dB → 2.8 dB と 1.5〜2 倍になり、誤読は悪化しなかった（1/24 行）。茜では、声優の録音が怒りのとき静かな行より 47 Hz
高いのに対し、一本の参照は逆向き（−24 Hz）、感情別の参照は同じ向き（+38 Hz）で、声の高さの幅も本物に近づいた。
**規則。**

- 演技は「`instruct` で頼む」ではなく「参照を替える」で付ける（クローンは `instruct` に従わない）。
- ラベルは記号で付く範囲と付かない範囲がある。**詰問・皮肉・からかい**は記号では分からない。そのような調子になる
  相づち・感嘆で始まる行は「要確認」として拾い、LLM で見直す（全話で 1 話あたり 0〜12 行、4.2 の D）。
- 感情の強い録音が少ないキャラがいる（小次郎の録音 364 本は大半が落ち着いた聞き込みの台詞）。参照にできるラベルが
  限られるので、ラベルが取れないキャラは「普通」に戻す。

#### 別エンジン（Style-Bert-VITS2）を試した結果

アクセントを外から直せる Style-Bert-VITS2 JP-Extra を、小次郎の録音（照合で選んだ 364 本・15.1 分）で学習して試した
（学習は RTX 5080 で 1 時間 26 分、VRAM 約 9 GB。コードと事前学習モデルは AGPL-3.0 なので、リポジトリの外に置いて
外部プロセスとして JSON Lines プロトコルで呼ぶ）。

| | 読み（比較 20 行、原文のまま、誤読語の残り） | 声の高さの幅 | 所見 |
|---|---:|---:|---|
| Qwen3-TTS | 80 % | 12〜13 半音 | 読みは弱いが抑揚は広い |
| Style-Bert-VITS2 | 33 % | 8.8 半音 | 読みは辞書で決まるので良い。抑揚が平たく、学習データが少ないので**滑舌が崩れる** |

- 滑舌の崩れは読みの誤りではないのでルビでは直らない。シード 8 通り、途中のモデル（6 000 / 7 000 / 8 000 ステップ）、
  ゆっくり（`length` 1.12）で作り直して検品が通るものを選ぶと、崩れた 10 行のうち 9 行が直った。直らなかった 1 行は
  どの設定でも同じ崩れ方をした。
- 感情のスタイルを指定すると、行ごとの声の高さと音量の差は付いたが（差 88 Hz / 5.8 dB）、幅は広がらず、話速が 3 割速くなり、
  誤読と崩れが増えた（4/24 行）。小次郎の録音に感情の強い台詞がほとんどなく、誇張すると学習していない領域に出るため。
- **決定: 全話は B1（Qwen3-TTS の感情別参照）で回す。** Style-Bert-VITS2 は見送り、茜のモデル学習は止めた。
- 一方、標準語の女性ナレーションでは、学習不要の配布モデル（`jvnv-F2-jp`、CC BY-SA 4.0 のクレジットが要る）が、
  訛りの点で Qwen3-TTS より適していた（[photo-video-knowhow.md](photo-video-knowhow.md) 2.4）。
  **規則:** 声の不満が「読み」か「訛り・抑揚」か「棒読み」かを先に切り分ける。読みはルビ、棒読みは感情別の参照、
  訛りはアクセントを辞書で付けるエンジン。三つは別の問題。
- アクセントの自動採点は自然さの指標にならなかった（声優本人の録音のほうが辞書の予測から外れる: 予測どおりの
  上下 49 % に対し、合成は 66 %）。イントネーションは耳で選ぶしかない。

#### 合成の運用

- **速度。** 初期の測定では RTX 5080 で 1 行約 1 秒（モデルの読み込みは 10〜20 秒、VoiceDesign の初回は取得込みで 122 秒）。
  全 30 話の一括実行では、合成の 1 周目は 1 話あたり 173〜310 行（例: 第 3 話は 242 行で 20 分）で、**1 行約 5 秒**
  （手順書の見積りは 6 秒）。初期の 1 秒との差の原因は未切り分け（感情別の参照の準備、行の長さ、検品を挟む運用などが
  考えられるが、測っていない）。GPU は 1 台なので、合成は直列にして話ごとに分け、
  `script.synthesize` の差分とキャッシュで、止めても続きから回す。
- **GPU の占有。** 別のプロセス（マイナー）が GPU の 97 % を使っていると、1 行 30〜60 秒になった。
  **規則:** 遅いと感じたら先に `nvidia-smi pmon` で占有を見る。`extras_voices.py --design` も、GPU が使用中だと警告を出す。
- **音量。** クローンの声とプリセットの声は 10 LU 以上違う。`anime.build` の `levelVoices`（既定オン）で
  中央値に揃え、`anime.check` の `loudness` 警告で確かめる。補正は中央値から 12 dB までなので、ゲームの録音自体が
  それ以上外れているもの（全話で中央値より −6〜−20 LU の行が散発した）は警告として残る（4.2 の F）。
- **録音を壊さない。** 録音のある行は合成しない。参照 WAV は名前・サイズ・更新時刻で同一性を見る。
- **実行環境。** Python は `-X utf8 -I`（隔離）で動く。そのためユーザーサイトの `pip install --user` は見えない。
  venv かインタプリタに入れる。1 時間何も出力しないスクリプトは止める。
- **訛り。** Qwen3-TTS の日本語は、読みをルビで直しても方言のような訛りが残ることがある（利用者の指摘、2026-11-09）。
  標準語の語りが要るなら、アクセントを辞書で付ける Style-Bert-VITS2 の配布モデル（女性は `jvnv-F2-jp`、学習不要、
  CC BY-SA 4.0 のクレジットが要る）を `script.synthesize` の `script`・`model` で呼ぶ。詳細は
  [photo-video-knowhow.md](photo-video-knowhow.md) 2.4。EVE の全話は Qwen3-TTS（B1）で作ったので、この訛りへの対処は
  していない（4.2 の C）。

### 3.4 立ち絵

**何が起きたか（差分が無い）。** ゲームの立ち絵 94 枚は、表情ごとの別絵（`NN` は表情・姿勢の番号）で、同じ表情の閉口 / 開口、
閉眼 / 開眼の対が無い。したがって 2 枚の切り替えでは口パクも瞬きもできない。

**直し（1）: 規約で台本に結び付ける。** 口と瞬きの画像は外で用意し、ファイル名の規則で台本に流し込む。
`<元の名前>_a / _i / _u / _e / _o / _blink`（任意で `_open`、口が開いて描かれた元絵には `_closed`）。**元絵と同じキャンバス
サイズ、同じ位置**にし、`anime.build` が元絵の上に重ねる。`sprite_variants.py` が、ある画像だけを台本に書き、
足りないものを警告する（設定済みは上書きしない。`--list` で必要な一覧を出す）。

**直し（2）: Gemini 生成より切り貼り。** Antigravity / Gemini の生成画像は、1024×1024・白背景で出て、位置や線も描き直され、
規約に合わなかった。口の矩形だけを元絵に貼り戻す後処理（特徴点で位置合わせ→口の楕円内の変化した画素だけ貼る）で
使える形にはなった（アカネ 48 枚と小次郎 18 枚）が、決定は**別表情から口を切り貼りする**道具（`mouth_cutouts.py`）を
主にすること。同じ衣装の別表情は、目と口の周りだけが違うことが多く、口の矩形をそのまま貼ると継ぎ目がない。
開いた口かどうかは、口の矩形が元より増やす「肌色でない画素」が 8 以上あるか、で決める（閉じた口の別形、たとえば
への字は +8 未満）。17 コード・94 枚のうち 51 枚が 5 母音を得て 331 ファイル。残りは、他の姿勢と頭が描き直されていて位置が合わない、
手で口が隠れる、全部の口が閉じている、のいずれか。**規則:** 画像モデルの出力は「位置が動かない」保証がないので、
後処理で元絵に貼り戻すか、元絵から切り貼りする。重ねて 50 % 透過で見て、口（目）以外に二重線が出ないか確かめる。

**瞬き。** 閉眼の元絵が無いので、切り貼りでは作れない（目を閉じた笑顔の絵が 2 枚あるが、普通の瞬きではない）。
Gemini 版で補う。小次郎は髪で目が隠れる 3 枚があり、瞬きは元絵の複製にして動かさない。
**組み立ての規則:** 瞬きの絵は口を閉じた全体絵なので、口が開いている間は瞬きを待つ（実装済み）。瞬きの時刻は行の位置で
固定されるので、組み立て直しても同じ瞬きになる。

**配置。**

- ゲーム素材は背景 640×448、立ち絵 320×448（一部 432×448）。1080p の中央に 100 % で置くと小さく浮く。
  **立ち絵は下揃え（`spriteAlign: "bottom"`）、背景と同じ倍率（`spriteScale: 241` = 1080 / 448）** にする。
- 主人公は、自分のルートでは立ち絵が一度も表示されないので台本に出ない。同じ立ち絵はデータにある。
  `protagonist_sprites.py` が、表情の無い主人公に全ての立ち絵を割り当てる。ただし脚色済みの 29 話は
  全ゲームのキャラクター表を持つので、このツールは何も変えなかった（1 ルートだけから切った台本で意味がある）。
- 会話の相手（立ち絵のある側）が、立ち絵のない主人公の行で消えたり出たりする。**直し:** 相手の行に `slot: 3` を付けると、
  他の人が話す間も右に残る。ゲームどおり中央に置きたいときは `rightX: 0.5` で置き場所だけ変えられる。
- 回想 CG の場面に立ち絵が出る。**直し:** 場面に `hideCharacters: true`。

### 3.5 口パクの方式

音量包絡だけで開閉を決める（モデルなし、決定的）。声の大きさを話者自身の大きい部分に対して測り、ヒステリシス
（開いた水準の 3 dB 下まで閉じない）と最短時間 50 ms、絶対下限 −50 dBFS で、静かな部屋で口が開かないようにする。
母音の画像は、読み（`reading`、なければルビ込みの本文）から拍を作り、声が出ている区間に**等間隔**で割り当てる。
音そのものは聞かないので、伸ばした音は短く切られ、漢字ばかりの行は開口のみに落ちる。
**規則:** 漢字の多い行には `reading` を付ける。母音の画像を持つ立ち絵には必ず `openImage` も持たせる。

### 3.6 擬音と効果音

- **何が起きたか。** 効果音の無い擬音の行（物音の文字起こし）を TTS が読むと、棒読みの声になる。
  また、効果音を声のトラックに置くと、声の音量に揃えられて**大きすぎる**（ゲームの効果音は一つひとつが
  最大音量に近く、扉が叫び声と同じ大きさになる）。点だけの行（沈黙の表現）は、合成の対象になって読まれてしまう。
- **直し。** 台本の `spoken: false`: 字幕は出すが声は作らず、口も動かない。音は `sfx`（A3）に置く。行の長さは
  max（効果音の長さ、字数 ÷ `charsPerSecond`、0.8 秒）＋間。`onomatopoeia.py` が、効果音を声として持つ行、効果音キャラの行、
  カタカナだけの擬音などを規則で見つけて印を付ける（第 1 話では 23 行: 効果音ありが 16 行、無音の間が 7 行。
  読み上げのまま残した曖昧な 6 行は見送り）。効果音は声の音量より `effectsBelowVoiceLu`（10 LU）下に揃え、
  上げる量は最大 6 dB、0.4 秒未満の短い音は測れないので `sfxGainDb`（−10 dB）。`anime.check` の `effect-loud` で確かめる。
  点だけの行で録音のないものは `direction`（無音の間）に直す（第 1 話では 26 行）。`episode_plan.py` も、
  点だけの録音なし行を前の行の間に足す（0.6 秒）。
- **規則。** 擬音は読まずに字幕だけ、音は A3 に声より 8 dB 以上（既定 10 LU）小さく。点だけの行は無音の間。
  ゲームの擬音クリップ（`j_擬音` など）は人の声ではなく効果音で、同名の効果音フォルダのファイルと同じ音
  （相関 0.99、AHX 版が 20 ms 遅れ）。

### 3.7 画面と書き出し

- **黒帯。** PS2 の素材は 640×448（4:3 に近い）。1080p の 16:9 に収めると左右に黒帯が出る。決定は**そのままの 4:3**
  （`backgroundFit: "fit"`）。画面いっぱいにする選択肢（`fill`、立ち絵は `spriteScale: 300`）は、背景の上下を
  44 ピクセルずつ切り、立ち絵が背景上で約 130 ピクセル高く立つ。
- **解像度。** PS2 の素材をそのまま拡大して作り、観て問題があればアップスケールを検討する、という決定。
  リニューアル版の素材は手元に無い。
- **書き出し。** 1080p・24 fps・H.264。30 分の話が 11〜13 分（約 60 fps 相当）で書き出せる。
  ただし**ファイルが大きい**: 27〜31 分の話で 0.9〜3.0 GB、64〜66 分の話で 4.2〜4.3 GB。
  30 本で約 60 GiB。ビットレートの指定はまだ詰めていない（4.2 の J）。
- **作業フォルダはディスクの速いほうへ。** 作業用の `E:` は HDD なので、話ごとの作業フォルダ（合成 WAV、段階ごとの台本、
  プロジェクト、mp4）は SSD の `F:\Temp` にジャンクションで置いた（第 4 話以降の実体は `F:\Temp\eve_out\epNN`）。
  台本や手順書のパスは `E:` のまま変わらない。
- **間。** ゲームの録音は前後に約 0.28 秒の無音を含むので、`pause` を 0.2 にした（第 1 話の推奨設定）。
  録音のない行は 7 字/秒で長さを見積もる。
- **大きな台本。** 字幕トラックは 1 本入れるたびに並べ替えるので遅い。全話の連結はせず、話ごとに組み立てる。
  1 つの音声が 1 時間を超えるもの、シーケンスが 100 時間を超えるものは使えない。

### 3.8 並列セッションと運用

- **担当ファイルを分ける。** 同じチェックアウトを共有するので、担当以外のファイルは触らない、ブランチを変えない、
  stash・reset をしない。コミットは 1 つのセッションが、タスクごとに**明示的なパス**で行う（1 コミット 1 タスク）。
- **ビルドの衝突を避ける。** Rust を触るセッションは `CARGO_TARGET_DIR=target/agent-<名前>` にする。
- **GPU は 1 本。** 合成は常に 1 プロセス。他の GPU 作業と競合させない。手順書は、始める前に毎回 `nvidia-smi` で
  使用率と VRAM を見て、マイナーや LM Studio（モデルを載せたまま）が動いていたら**利用者に止めてもらう**（自分では止めない）
  と決めている。
- **作品を入れない。** `out/` は作品のテキストを含むので `.gitignore`。作品のテキスト・画像・音声、台本の実物、
  合成した音声はリポジトリに入れない。データには読み取りだけで触る。
- **引き継ぎメモ。** 各セッションは共有ノートフォルダに `task-*.md` を残す（できたもの、重要な発見、残り）。
  下流の数字（行数、場面 id、合成のキャッシュ）は、上流（順路）を直すと全部変わる。順路を変えたら下流の作り直しを計上する。
- **品質ゲート。** コミットの前に `cargo xtask ci`（fmt / clippy / test / layers / assets / wasm）と、Python の
  `tools/eve_burst/tests` を通す。
- **機械で判定できる形にする。** LLM に任せる工程（脚色）も、`check_adaptation.py` と `script.validate` の終了コードで
  合否を決める。人が全部読む運用にしない。
- **モデルの使い分け。** 内容の判断が要る仕事（脚色、感情ラベルの見直し）は Opus、手順書どおりに話数順に回す仕事は
  Sonnet 1 本、と分けた。Sonnet には例外の一覧（3.9）を渡し、該当したら自分で直さず Opus に回す。

### 3.9 全話の一括実行（`episode_run.py`）

**何が起きたか。** 1 話を仕上げるだけで、声の割当、立ち絵の流し込み、擬音の印付け、差分画像、感情ラベル、読みの名前辞書、
感情別の参照、合成、読みの検品（最大 3 周）、組み立て、検査、書き出しと 10 以上の道具を順に呼ぶ。30 話を手で回すと、
どこまで済んだかが分からなくなり、途中で止まるたびに最初からになる。
**直し。** `episode_run.py` が、段階ごとに成果物（`epNN.<n>-<段階>.fcscript.json`）を作業フォルダに残し、
**成果物が入力より新しい段階は飛ばす**。止まったら同じコマンドをもう一度実行すれば続きから進む（合成は FilmCraft の
キャッシュで続きから）。ある段階だけやり直すときは `--force <段階>`。手で直したいときは段階ファイルを直接直して
同じコマンドを再実行する（直したファイルより後の段階だけやり直しになる）。結果は `epNN.result.json`
（`ok`、尺、検査のエラー・警告、`misreadsLeft`、`labelsToReview`、`spritesWithoutMouth` / `spritesWithoutBlink`）に集約する。
手順書は [eve-burst-episode-run.md](eve-burst-episode-run.md)。第 1 話（v8）と第 2 話を Opus のセッションが通して確かめ、
第 3 話以降は Sonnet のセッション 1 本が話数順に回した。

#### B（中）数字＋助数詞の誤読が 3 周しても残る

2. 数字と助数詞は、変換時または脚色時に `reading` へ最初から書く規則表にする（実録動画では、数字と単位・箇条の番号を
   最初から仮名にして、誤読判定を 7 → 1 → 0 行にできた: [photo-video-knowhow.md](photo-video-knowhow.md) 2.4）。
3. 認識器の期待読み（pyopenjtalk-plus）が助数詞の音便を扱えないなら、期待読みの側に上書き表（`overrides.json`）を足す。
4. 1 行だけ直すときは `script.synthesize` の `ids` と `force`。

#### C（高）声の自然さ: 訛り・抑揚・棒読み

**現状:** 読みはほぼ直り、棒読みは感情別の参照（B1）で改善した（3.3 の数値）。しかし**訛り・抑揚の自然さは数値で測れず**、
全話を通して利用者が聴いた評価は未取得。実録動画では、Qwen3-TTS のプリセット声に方言のような訛りが残った。
**対策（効果の見込みが大きい順）:**

1. まず聴く。各話から数行を抜いて、問題を「読み」「訛り・アクセント」「棒読み」に分類する（三つは別の問題、3.3）。
   ランダムに各話 5〜10 行なら 30 話で 150〜300 行、1 本の聴き比べページにまとめられる（案）。
2. 棒読みが残るなら、感情ラベルの見直し（D）と、ラベルごとの参照の質を上げる（4 秒以上の録音が無いラベルは、
   短い録音のつなぎのままになっている）。
3. 訛り・アクセントが気になるなら、アクセントを辞書で付けるエンジンを、役を絞って使う。学習不要の配布モデル
   （`jvnv-F2-jp` など）は女性役に使えるが、**クローンした声とは声質が変わる**。キャラクターの声の同一性とのトレードオフで、
   聴いて決める。小次郎の Style-Bert-VITS2 は、学習データ 15 分では滑舌が崩れ抑揚も平たかった。学習データを増やす
   （他の話者の録音を足す、感情の強い台詞を含める）と改善する見込みはあるが、**未検証**。
4. Best-of-N（シードを変えて N 本作り、検品が通って音素誤り率の低いものを選ぶ）。Style-Bert-VITS2 では 10 行中 9 行が
   直った実績がある。Qwen3-TTS は `filmcraft_tts.py` にシード指定が無く、**未実装**。
5. Qwen3-TTS の追加学習は見送りを維持する（16 GB では 0.6B のみ、公式スクリプトに未修正の不具合、日本語の成功報告なし）。

#### D（中）感情ラベルの手直し

**現状:** 記号と表情番号で付けたラベルのうち、皮肉・からかいの調子になる相づち・感嘆で始まる行が「要確認」になる。
第 2〜28 話で 99 行（1 話 0〜12 行）。Sonnet は自分で直さず `episodes_review.md` に溜めた。
**対策:**

1. 要確認の行だけを Opus（または手元の LLM）にまとめて見直させ、`epNN.6-labels.fcscript.json` の `instruct` を直して
   再実行する（直したファイルより後の段階だけやり直しになり、変えたラベルの行だけ合成し直し）。100 行前後なら一度に見られる量。
2. 見直した結果の傾向（その種の行は「静か」「問い」のどれに付けたか）を `emotion_labels.py` の規則に戻し、
   次の作品では要確認を減らす。
3. 日本語で皮肉を示す語は限られるので、記号の規則に語の一覧を足す案もあるが、誤判定が増えるため、見直し結果を見てから決める。

#### E（中）声のない長い区間

**現状:** `silence` の警告が、第 2〜28 話の多くに 5〜13 秒の区間として出る。最終話（第 30 話、66 分、41 件）の後半は 5〜33 秒が集中する。原因は、声のない場面（ゲームの間、端末画面、地図、効果音と BGM だけの場面）が
そのまま残っているためと**推定**するが、場面ごとの確認はしていない。
**対策:**

1. 脚色の合否判定に「声のない区間の長さの上限」を足す（`anime.check` の `maxSilenceSeconds` と同じ基準を `adapt.py` の
   検査に入れる）。脚色で `direction` の `pauseAfter` に上限を付ける。
2. 意図した間なら、基準を上げて警告を出さない（利用者の判断）。
3. 必要な説明が抜けているだけなら、ブリッジの語りを足す（脚色の `generated` 行）。

#### F（中）ゲームの録音自体の音量の外れ

**現状:** `loudness` の警告が、声の中央値より −6〜−20 LU の録音で散発する（第 7・10・14・17・19・20・22・26・28・29 話など）。
`levelVoices` の補正が中央値から 12 dB までなので、それ以上外れたものは補正しきれない。
**対策（案）:** 補正の上限を広げる（ただし録音のノイズも一緒に上がる）、外れた録音だけ個別のゲインを持たせる、
リミッターを併用する。聴いて、補正が必要な外れか、演技としての小声かを分けてから決める。

#### G（低）字幕の長さと速さ

**現状:** 字幕が 0.25〜0.38 秒しか出ない（`caption-short`）、22〜24 字/秒で速い（`caption-fast`）警告が少数ある。
**対策（案）:** `anime.build` で、最短表示時間（0.4 秒）に満たない字幕を前後に統合するか表示を延ばす。速い字幕は、
その行の間（`pauseAfter`）を伸ばすか、脚色の段階で長い行を分ける。

#### H（中）瞬き

**現状:** 全話・全表情で瞬きの画像がない（手順書の `spritesWithoutBlink` は「ほぼ全部」）。ゲームに閉眼の元絵がなく、
切り貼りでは作れない。Gemini 版の瞬きは、小次郎では髪で目が隠れる絵が多く元絵の複製（動かない）。
**対策:**

1. 閉眼の絵を外部で描く（枚数の見積りは `sprite_variants.py --list` が出す）。出力は、元絵と同じキャンバス・同じ位置にし、
   後処理で目の矩形だけを元絵に貼り戻す（口と同じ方法）。
2. 目を閉じた絵が 2 枚（笑顔）あるので、その目の矩形を同じ姿勢の他の表情に貼る方法は、普通の瞬きより「笑い目」になるため
   不向き。
3. 瞬き無しを許容する。静止画の立ち絵の作品では珍しくなく、口の動きがあれば動画としては成り立つ。優先度は低い。

#### I（中）口の差分のない立ち絵が多い

**現状:** 切り貼りで口の差分を作れたのは 94 枚中 51 枚で、`aqu gul kag kat koj mar sir uwe` の 8 コード（主要な脇役を含む）は
1 枚も作れていない（頭が描き直された別姿勢か、手で口が隠れる絵のため）。そのため全話で、結果ファイルの
`spritesWithoutMouth` に毎話 0〜12 枚が並び、これらの登場人物は話しても口が動かない（動画としては作れる）。
手順書の「既知の欠け」の一覧は小次郎・まりな・茜の 2 枚・他 2 枚だけで、実際の欠けより短い。話ごとの報告が「なし」と
なっていたのは、一覧との照合が人の目に任されていたためと**推定**する。
**対策:**

1. 照合を機械にする。`episode_run.py` が `spritesWithoutMouth` を「既知（決定済みの欠け）」と「新規」に分けて結果ファイルに
   書き、新規があれば例外として止める（または全話分を一度だけ集計して一覧を正す）。
2. 口を動かしたい登場人物を決める（出番の多い順に、話数 × 行数で数える）。候補は脇役の 4〜5 人。
3. 作る方法: ①外部の画像モデルで描いた口を元絵に貼り戻す後処理（茜 48 枚と小次郎 18 枚で成立した。ただし利用者の決定で
   Gemini 版は使わないことにしてある。やり直すなら決定を改める）、②外部の描き手に依頼する、③切り貼りの道具に、
   他の姿勢の絵から頭ごと合わせる位置合わせを足す（頭が描き直されていて、最良の位置でも顔の画素の約半分が違ったので
   見込みは薄い）。
4. 作れない間は、開閉 2 枚（`openImage` のみ）に簡略化するか、口が閉じた絵と開いた別表情を交互に出す代替は顔が変わるので避け、
   口は動かさないままにする。

#### J（低）書き出しの容量

**現状:** 30 本で約 60 GiB（1 話 0.9〜3.0 GB、長い話は 4 GB 超）。
**対策（案）:** 書き出しプリセットでビットレートまたは品質（CRF）を指定する。確認用の低ビットレート版と、公開用を分ける。
現在の設定値は**確認していない**。

#### K（高）旧順路から作った脚色版

**現状:** 書き出した 30 話は旧順路の脚色版。現行の順路（テレポート 0、両編 53 278 行）から作り直してはいない。
**対策:**

1. まず差分を機械的に調べる。旧順路と現行の場面 id の集合の差（欠けた場面、重複して出る場面）を、話ごとに数える。
   実害が小さければそのまま、大きければ該当話だけ作り直す。
2. 全部作り直すなら、`episode_plan.py` → 脚色（Opus、話ごとに並列）→ 声の割当 → `episode_run.py` の順で、合成だけで
   約 14 時間（GPU 直列）、全体で 1 日以上。キャッシュは行 id が変わるので使えない。利用者の判断。

#### L（低）リニューアル版の素材

**現状:** 手元は PS2 版のダンプのみ。1080p には拡大して使っており、アップスケールは「観て問題があれば」と決めた。
**対策:** リニューアル版の素材を展開したら、`assets.py` に相当する名前の対応を作る。アップスケール（外部ツール）は、
PS2 版のサンプルの画面を観てから決める。

#### M（低）その他の既知の限界

- 母音の口形は読みに対する等間隔の割当で、実際の音は聞かない。音素のタイムスタンプ（Whisper の単語時刻など）を使う方式は未着手。
- 立ち絵は静止、同時に出るのは左右の 2 人まで、場面転換は切るか黒からのフェードのみ（未着手）。
- 順路の限界: 他方の側は同じ方針で動かすので実プレイヤーの順とは限らない。船の往復は約 120 回（ゲームの廊下そのもの）。
  必要なら `--choices` で手動で誘導する。
- 大きな台本の性能: 字幕トラックの一括挿入が遅い。話ごとに組み立てて回避している。

#### N（低）読みの道具が 2 本ある

**現状:** `tools/eve_burst/tts_readings.py`（2 つの認識器、同形異音語が見える、テスト 19 件、全 30 話で使用）と
`tools/qwen3-tts/readings.py`（Whisper medium のみ、未コミット）の役割が重なり、どちらを残すか決めていない。
**対策（提案）:** `tts_readings.py` を残す。理由は、検出が深く、全話で使った実績とテストがあるため。`readings.py` にだけある
機能（名前辞書の扱い）があれば `tts_readings.py` に取り込み、残りは消す。

#### O（低）作り直しで手直しが消える

**現状:** `voice_refs.py` で参照を作り直すと `refText` の修正が元に戻り、`voice_styles.py pick` を作り直すと、手で選んだ
2 種（小次郎の驚き・呆れ）が消える。
**対策（案）:** 手で直した値を、道具の出力とは別の上書きファイルに分け、作り直した結果の上に重ねる。作り直す前に
`tts_readings.py refs` で照合する。

#### P（中）台本の声の設定を変えるとキャッシュが全部外れる

**現状:** `characters` の `voice` を変えると全行のキャッシュが外れ、選んだテイクも上書きされる（実録動画で経験）。
感情別の参照では、ラベルのある行だけが鍵に入る作りにして軽減した。
**対策:** 声を替えるだけなら、台本は触らず `script.synthesize` の `script`・`model` で替える。声の設定を変えるときは、
全行の再合成（約 14 時間）を覚悟して、話ごとに分けて回す。

#### Q（中）通し視聴と受け入れ

**現状:** 話ごとの自動検査は通ったが、30 本を人が通して観ていない（未確認）。継ぎ目（話の頭と終わり）、前の話で削った行を
後の話が前提にしていないか、感情別の参照の自然さ、は自動では測れない。
**対策:** A を直したあとに、話の継ぎ目だけを順に観る（各話の最初と最後の 1〜2 分）。次に C の抜き聴き。

### 4.3 次にやること（順）

1. （済）台本の取り違え。第 2〜30 話の入力は最終の `adapted/` と一致。取り込みの検査も入れ済み（4.2 の A）。
2. K: 旧順路との差分を調べる（数分）。実害の有無で、全部作り直すか決める。
3. C: 抜き聴きで、読み・訛り・棒読みを分類する。
4. D・B: 要確認の感情ラベルの見直し（99 行）と、数字＋助数詞の誤読の切り分け。
5. E・F・G: 検査の警告を減らす（脚色の合否、音量、字幕）。
6. I: 口の差分のない立ち絵の照合を機械にし、口を動かしたい登場人物を決める。
7. H・J・L: 瞬き、容量、リニューアル版の素材。優先度は低い。

## 5. 小説（ゲームでない文字）から作るときの流用

### 流用できるもの

- **台本の形式と `script.validate`。** そのまま使える。`when`・`requires`・`route` は、時系列を入れ替える小説（回想・多視点）で
  使う。
- **合成・口パク・組み立て・検査・書き出しの全部**（`script.synthesize`、`script.lipsync`、`anime.build`、`anime.check`、`anime.run`）。
  台本が同じ形なら、ゲームでも小説でも同じ。
- **声の設計とクローン。** 小説には録音がないので、すべての話者が「設計してからクローン」の対象になる。
  男声の F0 窓、「高め」「しゃがれ」を避ける指示、1 回作って固定、は同じ。声を役名に結び付けて固定する考え（`extras_voices.py`）も流用できる。
- **擬音と効果音の扱い**（`spoken: false`、効果音は声より下、点だけの行は無音の間）。小説の擬音語にも当てはまる。
- **立ち絵の差分の規約**（`_a _i _u _e _o _blink`、同サイズ・同位置）と `sprite_variants.py`、配置の考え（下揃え、背景と同じ倍率、
  `slot`、`hideCharacters`）。
- **話数への切り方と脚色の枠組み**（`episode_plan.py`、`adapt.py`、`check_adaptation.py`）。小説では「録音のある行は削除だけ」の制約が
  なくなるので、**全行を書き換えてよい**。それでも、行 id を保つ、順序を変えない、機械で合否を判定する、は有効。
- **読みの検品**（`tts_readings.py`: 2 つの認識器で聞き返し、誤読語だけルビにして再合成を最大 3 周）。台本の形式が同じなら、そのまま使える。
- **感情ラベルと感情別の参照**（`voice.styles`、`emotion_labels.py` の考え方）。小説では表情番号が無いので、ラベルは文面と、
  LLM が台本化のときに付ける感情から付ける。
- **1 話の一括実行**（`episode_run.py` の段階ごとの成果物、再実行で再開、例外の一覧）と、取り込み時の突き合わせ（3.9）。
- **運用**（担当ファイルの分担、GPU 直列、品質ゲート、作品を入れない）。ルビ（青空文庫記法）は話すときの読みと表示の両方に使える。

### 流用できないもの

- **変換器 `eve_to_script.py`、順路の方針、ザッピング、`merge_routes.py`。** ゲームの命令列とフラグを解釈するためのもので、
  小説には分岐がないので要らない（複数視点の小説を日単位で並べたい場合の `when` / `requires` の考えだけは使える）。
- **`assets.py`、素材の名前の対応、`voice_refs.py`、`voice_styles.py pick`、`script.pickVoices`。** 元の録音と、行と録音の
  対応表があって初めて働く。小説では参照音声を自分で用意する（権利と同意に注意）。ラベル別の参照も録音からは選べないので、
  VoiceDesign で感情ごとに参照を設計してからクローンする、という使い方が考えられる（案。**未検証**）。
- **`mouth_cutouts.py`。** 同じ衣装の別表情が同じ体で描かれていることを前提にしたゲームの立ち絵向け。
  小説では立ち絵そのものを外で作る必要があり、口の差分も外で作って規約に合わせる。
- **ゲーム画面のサイズ（640×448）に由来する倍率（241 %）と黒帯の判断。** 素材のサイズに合わせて決め直す。
- **`game2script.py`** は文字のシナリオ（テキストゲーム）向けで、地の文と台詞が混ざった小説には向かない。

### 小説に固有の、まだ無いもの

- **小説 → 台本の変換（話者推定、地の文のナレーション化、ト書き抽出、場面分割）。** 未着手で、LLM の仕事とされている
  （[novel-to-anime.md](novel-to-anime.md) §1.1、§5）。台本を書き込むコマンド群（`script.*` の書き込み側）も未実装で、
  現状は JSON を直接書く。
- **ルビの付いた長文の読み。** ゲームの文では、合成した行の約 11 % に誤読があり、音読みの熟語が 6 割強だった（3.3）。
  漢字の多い小説では同程度かそれ以上と**推定**するが、小説では測っていない。
- **背景・立ち絵・BGM・効果音の素材。** 画像は生成しない方針なので、外部のツールで用意するか、利用者の素材フォルダを使う。
