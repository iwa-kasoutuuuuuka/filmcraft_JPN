# 文字から動画へ：機能とノウハウのまとめ

状態: **まとめ**（2026-11-06）。小説やゲームのシナリオ（文字）から、ボイスドラマ＋立ち絵＋背景＋字幕の
2D アニメを自動で作る仕組みについて、これまでに作った機能と、実際に回して分かったことを 1 か所に集める。
細部は各文書に任せ、ここでは「どの工程を何が担うか」「何が起きてどう直したか」「次にやること」を書く。

題材にしたのは、利用者本人の PS2 ゲーム「EVE burst error PLUS」の解析ダンプ（個人の技術検証。作品のテキスト・
画像・音声はリポジトリに入れず、公開もしない）。この文書にも作品の台詞は載せていない。数値は、各文書に書かれた
実測値と、作業セッションの引き継ぎメモの値だけを使う。測っていないことは「未確認」と書く。

関連文書の一覧は末尾の「参照した文書」にある。

## 1. 全体像

台本（JSON、プロジェクトの外）を**唯一の上流データ**にする。下流の素材とクリップはすべて台本の行 id で
追跡するので、台本を直したら、変わった行だけをやり直せる。人が見るのは最後の 1 回だけ。

```
文字（小説 / ゲームのシナリオ）
   │  ① 台本化   変換器（外部スクリプト）または LLM が *.fcscript.json を書く
   ▼
台本（行 id・話者・表情・場面・順路）
   │  ② 順路と話数   when / requires / route、merge_routes、episode_plan
   │  ③ 脚色（圧縮）  adapt.py、check_adaptation.py（LLM を話ごとに並列）
   ▼
話ごとの台本
   │  ④ 検証        script.validate
   │  ⑤ 声の割当    script.pickVoices / voice_refs.py / extras_voices.py / apply_voices.py
   │  ⑥ 合成        script.synthesize（差分・キャッシュ）  ← GPU 直列
   │  ⑦ 口パク解析  script.lipsync（音量包絡）
   │  ⑧ 立ち絵差分  mouth_cutouts.py → sprite_variants.py（台本に結び付ける）
   ▼
   │  ⑨ 組み立て    anime.build（Tick 精度、1 回の取り消しで戻る）
   │  ⑩ 検査        anime.check
   │  ⑪ 書き出し    export（anime.run が通しで呼ぶ）
   ▼
人が観る → 台本か設定を直して ④ 以降を再実行（変えた行だけ）
```

`anime.run` が ④ → ⑤（任意）→ ⑥ → ⑨ → ⑩ → ⑪ を 1 回で通す。⑦ の口パク解析は ⑨ の中で使われる。
その前の ①〜③ と ⑧ は外部の道具で、FilmCraft 本体には入れていない（タイトルごとに違うため）。

| 工程 | 担うもの | 場所 | 詳細 |
|---|---|---|---|
| ① 台本化（ゲーム） | `eve_to_script.py`（命令列を解釈して 1 本道にする）、汎用の `game2script.py` | `tools/eve_burst/`、`tools/game2script/` | [eve-burst-convert.md](eve-burst-convert.md)、[game-import.md](game-import.md) |

## 2. 機能一覧

### 2.1 台本の形式

`*.fcscript.json`（version 1）は、プロジェクトの外の独立した JSON。要点だけ書く（全項目は
[script.md](script.md)「Format」）。

- **characters**: `name`、`voice`（`refAudio` + `refText` でクローン、または `speaker` + `instruct` でプリセット）、
  `expressions`（表情名 → `image`、`openImage`、`vowelImages`（あ・い・う・え・お）、`blink`）、`defaultExpression`。
- **scenes**: `id`、`title`、`pov`、`when`（時系列に並ぶ文字列）、`requires`（先に見せる場面）、`background`、`bgm`、
  `transition`（`cut` / `fade`）、`hideCharacters`、`lines`。
- **lines**: `id`（全体で一意。音声ファイル名になる）、`kind`（dialogue / narration / monologue / direction）、
  `speaker`、`text`（話す内容かつ字幕。青空文庫のルビ記法を読みとして使う）、`reading`（話すときだけ置き換える仮名）、
  `expression`、`voiceFile`（既存の録音。ある行は合成しない）、`instruct`、`sfx`、`pauseAfter`、
  `generated`（ツールが足した行）、`spoken: false`（字幕だけで声を作らない擬音）、`video`、`subCg` / `subCgAnchor`、
  `slot`（1 左、2 中央、3 右）。
- **route**: 場面 id を見せる順に並べる。台本に無い場面は表示されない。
- 上限（1 行 4 000 文字、場面 1 万、行 20 万、ファイル 64 MB）を超える入力は敵対的なものとして拒否する。

### 2.2 コマンド

| 系統 | コマンド | 何をするか |
|---|---|---|
| `script.*` | `script.validate` | 台本の検査。エラー（id の重複、前提の順序、範囲外の `slot` など）と警告（時間の逆行、声が無い話者など）、統計（録音のある行 / 合成する行の数） |
| | `script.pickVoices` | 録音のある行の中から、キャラクターごとの参照クリップを選ぶ（2.5〜12 秒、6 秒に近い、落ち着いた行、話速が妥当）。`write` で台本に書く |
| | `script.synthesize` | 録音のない話す行を、キャラクターの声で `<out>/<id>.wav` に合成する。行ごとのハッシュを `manifest.json` に残し、2 回目以降は変えた行だけ。400 行ごとに保存するので、途中で落ちても続きから |
| | `script.lipsync` | 台本の全行について、口の開閉の時刻を `lipsync.json` に書く |
| `lipsync.*` | `lipsync.analyze` | 1 つの音声ファイルの開閉（`three: true` で半開きを足す）。音量包絡だけで決め、モデルは使わない |
| `speech.*` | `speech.synthesize` | 行のリストまたは 1 文を WAV とメディア項目にする。参照音声、プリセット、`instruct`、言語、モデル、デバイスを指定できる |
| | `speech.synthesizer` | 何が合成するか（Python と `filmcraft_tts.py` の場所、`--probe` の結果）を返す |
| `anime.*` | `anime.build` | 台本を新しいシーケンスに並べる（下表）。1 回の取り消しで戻る |
| | `anime.check` | 並べた結果の自動検査 |
| | `anime.run` | 検証 → 参照選択（任意）→ 合成 → 組み立て → 検査 → 書き出し（任意）を、最初に失敗した工程で止まりながら通す |

`anime.build` が作るトラック（詳細は [script.md](script.md)）:

| トラック | 内容 |
|---|---|
| V1 | 背景（場面ごとに 1 枚、ゆっくり寄る）。行の `video` がある間はそのムービー。`transition: fade` は黒からのフェードイン |
| V2 / V3 / V4 | 話者の立ち絵 / 口の差分（声が出ている間、母音ごと）/ 瞬き |
| V5〜V10 | `slot` 1・3 のときの左右の立ち絵と、それぞれの口・瞬き（2 ショット） |
| 最上段 | サブ CG（小窓） |
| A1 / A2 / A3 | 声（音量を揃える）/ BGM（場面の長さまで繰り返し、`bgmGainDb` −18）/ 効果音（声より 10 LU 下に揃える） |
| 字幕 | ルビを除いた平文を、文末・読点で切って長さに比例して配分 |

時間はすべて Tick（1 秒 = 254 016 000 000）で、行の長さは「音声の長さ＋間」、境界はフレームに乗る。

`anime.check` の種類: `offline`（素材がない）、`gap`（背景の穴）、`overlap`（声の重なり）は**エラー**。
`silence`、`loudness`（声の中央値から 6 LU 超）、`effect-loud`（効果音が声の中央値の 6 LU 以内）、字幕の
`caption-long` / `caption-fast` / `caption-short`、`no-audio`、`empty`、`no-voice` は警告。

### 2.3 台本の外の道具（Python、標準ライブラリのみ。例外は TTS 側）

`eve_to_script.py`（変換）、`merge_routes.py`（2 視点を日ごとに交互に並べる）、`episode_plan.py`（話数に切る）、
`adapt.py` と `check_adaptation.py`（脚色と機械検査）、`assets.py`（素材の名前解決）、`voice_refs.py`
（声の棚卸しと参照の選定）、`apply_voices.py`、`extras_voices.py`（エキストラの声を役名で固定）、
`protagonist_sprites.py`、`mouth_cutouts.py`、`sprite_variants.py`、`onomatopoeia.py`、
`tools/qwen3-tts/filmcraft_tts.py`、`readings.py`。

## 3. ノウハウ（工程ごと）

各項目は「何が起きたか → どう直したか → 規則」の順に書く。

### 3.1 台本化と分岐の順路

**分岐ゲームは命令列を解釈して 1 本道にする。** 文字を拾うだけでは足りない。フラグ、条件分岐、メニュー、
シナリオ間の移動を実際に実行し、選択肢を方針（policy）で選ぶ。ゲームに固有の部分なので、小説には要らない。

- **何が起きたか（往復で道がふさがる）。** 最初の方針（`explore`: 先読みして新しい内容がある選択肢を選び、
  行き詰まったらテレポート）は、日付順を通らなかった。小次郎編で日付ムービー 3 本（12/4〜12/6）が一度も再生されず、
  別の 1 本が 4 回再生され、2 つの場所が互いを指す往復が約 60 回続いて道がふさがった。12/3 が 9 616 行になった。
  **直し:** `days` 方針（既定）。①後の日に進む選択肢は最後に回す、②「次のメニューまでに新しいものがある」
  行き先を先に取る（往復の原因だった「先にあるものの合計」で選ぶのをやめる）、③行き詰まったら、メニュー選択だけで
  行ける最寄りの新しい場所を幅優先で探して歩く、④過去の日付ムービーをもう一度出す行き先は最後。
  **規則:** 探索は「その日に新しいものが残っている間は次の日に進まない」にする。テレポートは道が無いときだけ。
- **何が起きたか（共有フラグ）。** 両主人公は F0〜F255 を共有し、相手側でしか立たないフラグがある
  （一方の 12/4 の学校は、他方の側が立てるフラグを待つ）。一方の側だけを実行すると進めない。
  **直し:** **ザッピング**。もう一方の側を同じフラグで裏で進め（台本には書かない）、主の側が次の日に進む前と
  行き詰まったときに相手側を主の日の終わりまで進める。12/6 の 2 つの端末のように、互いにフラグを渡し合う箇所では、
  相手側がまず待つ（主の側がフラグを変えたときだけ数える）。合流場面（2 つの側が出会う）の手前で相手側は止まり、
  主の側が行き場を失ったら合流する。
  **規則:** 共有状態のある複数視点は、実際に切り替えて遊ぶのと同じ順で動かす。
- **何が起きたか（キーパッド）。** 数字キーを順に押して場所に戻るメニューは、場所だけで状態を区別する探索では見つからない。
  **直し:** 場所だけで見つからないときに限り、途中で変わったフラグも状態に含めて探し直す（最初からフラグ込みで探すと
  別の行き止まりができて、日付ムービーを飛ばした）。
  **規則:** 状態の区別は粗いほうから始め、見つからないときだけ細かくする。
- **結果。** 両編ともテレポート 0、日付ムービーは各 1 回で順番どおり。小次郎編 30 077 行（日ごとの最大は 12/7 の 7 520 行、
  のちに船の部分を直して 12/6 が 8 907 行、12/7 が 3 844 行）。両編を日単位で交互に並べると 2 709 場面・53 278 行
  （順路修正の途中では 2 728 場面・52 707 行）。
- **規則（安全）。** 変換は命令数・行数・移動数・各命令の訪問数・選択肢ごとの繰り返しに上限を持ち、敵対的または
  ループするシナリオは理由を付けて終わらせる。1 回の変換は約 10 秒。

**`when` と `requires` を必ず書く。** 変換器は最初、視点（`pov`）だけで `when` / `requires` を書かず、
2 つの視点を並べても `script.validate` が時系列と前提を見られなかった。日付画面と日付ムービーの出現で日を進め、
`D03-0012` のように「日＋場面番号」で書く。両視点が合流する場面は反対側の最後の場面を `requires` にする。
`merge_routes.py` が日ごとに A → B と並べ、`requires` を満たす順に直し、id に接頭辞を付ける（音声ファイル名は
id なので、合成も別名になる）。
**規則:** 台本を作る側が時間と前提を書き、検査は `script.validate` に任せる。

**1 話の長さで切る。** 日単位で切ると 1 話が数時間になる（12/3 の小次郎編 5 876 行 × 約 2.65 秒 ≒ 4 時間 20 分）。
`--episode-lines 600` で場面の境目で切ると 1 話約 26 分。**規則:** 1 行の平均は声＋間で約 2.65 秒。話数は行数上限で決め、
場面は切らない。

### 3.2 話数と脚色（圧縮）

**何が起きたか。** 無編集で並べると、両編 52 707 行で約 39 時間（テレポート解消前の見積り）。解消後は 53 278 行で
見積り 43.8 時間、繰り返し部分を削って 36.3 時間（`episode_plan.py` の機械的な削り: 3 行以上続く既出の会話、
点だけの録音なし行、空になった場面）。利用者の決定は 1 話 24〜30 分、全体で 28〜30 話、最終話は 1 時間程度。

**直し。** `episode_plan.py` が 29 話（27 分 × 28 話＋最終話 60 分）の下書きを作る（全体で約 37〜39 % を残す）。
各話を LLM セッションが 1 話ずつ並列に脚色し、`adapt.py` の編集リスト（delete / rewrite / merge / insert / reading /
pause）を適用し、`check_adaptation.py` と `script.validate` で機械的に合格判定する。話と話のつなぎは、日ごとに
別のセッションが読んで、前の話で削った行を後の話が前提にしていないかを確かめ、編集リストの側で直した。
最終的に 30 話・約 14.5 時間（各話 26.5〜29.0 分、最終話 62.9 分）で全部合格。ただしこの脚色済みの 30 話は、
順路修正（テレポート解消）の**前**の順路から作ったもので、現行の順路からは作り直していない。

**規則（脚色）。**

1. **録音のある行は削除だけ。** `text`、`speaker`、`kind`、`voiceFile` を変えない（録音と合わなくなる）。`reading` の追加は可。
2. 録音のない行（主人公の台詞の大半と語り）は、筋を変えない範囲で書き換え・統合してよい。書き換えた行は id を保ち
   `generated: true`。統合は最初の行の id を残す。
3. 新しい行（ブリッジ）は新しい id（`<場面>-g01`）、`generated: true`、録音なし。
4. 順序は入れ替えない。場面は削れるが足せない。
5. 脚色が足してよいもの: 間（`pauseAfter`）、効果音、表情、読み、`direction`。
6. 合格判定は機械でやる（規則違反と尺。終了コード 0 / 1 / 2）。例外は 2 つだけ（録音を台詞の代わりに鳴らす `voiceOnly`、
   番号付きの端役を別の登場人物に付け替える `speaker`）。
7. 人が読むのは最後だけ。脚色の指示は「台本ファイルと形式と規則」だけを渡す。コードではなく内容の仕事。

**ゲームの間（ま）の情報は落ちる。** 選択肢、ハッキング画面、地図、フェード、声の停止は変換で無視される。
**規則:** これは道具の問題ではなく演出の問題なので、脚色でト書き（`direction` の `sfx`・`pauseAfter`）を足して補う。

### 3.3 声

#### 参照クリップの選び方

**何が起きたか。** 主人公 2 人は、自分のルートでは台詞が文字だけで録音がない（全 52 033 行のうち録音のある行は
16 159 行、31.1 %。未収録 35 874 行のうち、この 2 人の分が約 32 700 行）。声は、脇役として登場する別ルートの録音から
クローンするしかない。自動選定の第 1 候補（4.5 秒の参照）で合成した小次郎は、参照が問いかけで語尾の上がる調子だったため、
心の声まで高く明るくなった（基本周波数 F0 は参照が 148 Hz、合成が 150〜187 Hz）。
**直し。** 落ち着いた言い切りの 2 本をつないだ 11.9 秒の参照に替えると 103〜115 Hz になった。台詞・心の声・語りのすべてに
同じ参照を使い、全話の台本も差し替えた。
**規則。**

- **参照クリップの調子が、合成全体の調子を決める。** クローンは `instruct` に従わず、録音に従う。
  話す相手に向かう録音は、独白に使うと外向きになる。
- 聴く前に、基本周波数（自己相関）で確かめる。声の窓の目安は男声 60〜160 Hz、女声 165〜300 Hz、
  子供 200〜450 Hz（`extras_voices.py` の採用基準）。
- 参照は 4〜12 秒の落ち着いた全文（`！` や感嘆詞、笑い・叫び、ほぼ点だけの行は避ける）。1 本で足りなければ、
  同じ話者の落ち着いた 2 本をつなぐ。自動の選定（`voice_refs.py`）は、文面の調子 40 点を含む 100 点満点で採点するが、
  音声側に調子のラベルは無いので、最後は F0 と耳で決める。
- 参照の `refText` を付ける（付けないと話者埋め込みだけで、クローンの質が下がる）。声の権利と同意に注意
  （[text-to-speech.md](text-to-speech.md)）。

#### 設計してからクローン

**何が起きたか。** 日本語の男性プリセットが Qwen3-TTS に無い。男性の端役（守衛・警備員・フロント・警官など、約 1 100 行）に
声が要る。VoiceDesign（文章で声を作る）に「低い声の男性」と指示すると、守衛は F0 86 Hz の男声になったが、
「やや高めの声」と書いたフロントは 211 Hz、「しゃがれた低い声」と書いた警官は 235 Hz（94〜308 Hz で不安定）、
クローン後は 273 Hz と、**女声域に飛んだ**。
**直し・規則。**

- 1 文を VoiceDesign で作り、その WAV を参照にして Base モデルでクローンする（"design, then clone"）。
  設計した声は 1 行ごとに少し変わるので、**1 回作って固定**する。同じ指示でもう 1 文作った例は 86 Hz のまま、
  クローンした 2 行は 85 / 87 Hz で、声は保たれた。
- 指示文は「低い声の男性」を明示し、「高め」「しゃがれ」の修飾は避ける。役ごとに 2〜3 回作り、F0 が窓に入るものを採り、
  最後に必ず聴く。F0 は聴感の代わりにならない（実際、新しく設計した 10 本は 2026-11-06 に利用者が聴いて承認している）。
- 台本側は `refAudio` / `refText` のままなので、FilmCraft 本体は変えなくてよい。

#### 役名で声を固定する

**何が起きたか。** 変換器は話ごとに無名の話者へ `n001`… と振り直すので、同じ守衛が話ごとに違う id になり、
id で声を決めると話ごとに声が変わる。
**直し。** `extras_voices.py` は**表示名**で声の種類（クラス）と参照を引く。78 の役名に 13 の声を割り当て、
同じ場面で話す 2 人が声を共有しないよう、行数の少ないほうを同じ性別の別の声に移す（大きな役は動かさず、
動かしたくない小役は声を固定できる）。
**規則:** 声は id ではなく役名に結び付け、表は台本の外に置く（再実行で既存の編集を保つ）。

#### 合成の運用

- **速度。** RTX 5080 で 1 行約 1 秒（モデルの読み込みは 10〜20 秒、VoiceDesign の初回は取得込みで 122 秒）。
  未収録 35 874 行（脚色前の全量）は約 10 時間。GPU は 1 台なので、合成は直列にして話ごとに分け、
  `script.synthesize` の差分とキャッシュで、止めても続きから回す。
- **GPU の占有。** 別のプロセス（マイナー）が GPU の 97 % を使っていると、1 行 30〜60 秒になった。
  **規則:** 遅いと感じたら先に `nvidia-smi pmon` で占有を見る。`extras_voices.py --design` も、GPU が使用中だと警告を出す。
- **音量。** クローンの声とプリセットの声は 10 LU 以上違う。`anime.build` の `levelVoices`（既定オン）で
  中央値に揃え、`anime.check` の `loudness` 警告で確かめる。
- **録音を壊さない。** 録音のある行は合成しない。参照 WAV は名前・サイズ・更新時刻で同一性を見る。
- **実行環境。** Python は `-X utf8 -I`（隔離）で動く。そのためユーザーサイトの `pip install --user` は見えない。
  venv かインタプリタに入れる。1 時間何も出力しないスクリプトは止める。

### 3.4 立ち絵

**何が起きたか（差分が無い）。** ゲームの立ち絵 94 枚は、表情ごとの別絵（`NN` は表情・姿勢の番号）で、同じ表情の閉口 / 開口、
閉眼 / 開眼の対が無い。したがって 2 枚の切り替えでは口パクも瞬きもできない。

**直し（1）: 規約で台本に結び付ける。** 口と瞬きの画像は外で用意し、ファイル名の規則で台本に流し込む。
`<元の名前>_a / _i / _u / _e / _o / _blink`（任意で `_open`、口が開いて描かれた元絵には `_closed`）。**元絵と同じキャンバス
サイズ、同じ位置**にし、`anime.build` が元絵の上に重ねる。`sprite_variants.py` が、ある画像だけを台本に書き、
足りないものを警告する（設定済みは上書きしない。`--list` で必要な一覧を出す）。

**直し（2）: Gemini 生成より切り貼り。** Antigravity / Gemini の生成画像は、1024×1024・白背景で出て、位置や線も描き直され、
規約に合わなかった。口の矩形だけを元絵に貼り戻す後処理（特徴点で位置合わせ→口の楕円内の変化した画素だけ貼る）で
使える形にはなった（アカネ 48 枚と小次郎 18 枚）が、決定は**別表情から口を切り貼りする**道具（`mouth_cutouts.py`）を
主にすること。同じ衣装の別表情は、目と口の周りだけが違うことが多く、口の矩形をそのまま貼ると継ぎ目がない。
開いた口かどうかは、口の矩形が元より増やす「肌色でない画素」が 8 以上あるか、で決める（閉じた口の別形、たとえば
への字は +8 未満）。17 コード・94 枚のうち 51 枚が 5 母音を得て 331 ファイル。残りは、他の姿勢と頭が描き直されていて位置が合わない、
手で口が隠れる、全部の口が閉じている、のいずれか。**規則:** 画像モデルの出力は「位置が動かない」保証がないので、
後処理で元絵に貼り戻すか、元絵から切り貼りする。重ねて 50 % 透過で見て、口（目）以外に二重線が出ないか確かめる。

**瞬き。** 閉眼の元絵が無いので、切り貼りでは作れない（目を閉じた笑顔の絵が 2 枚あるが、普通の瞬きではない）。
Gemini 版で補う。小次郎は髪で目が隠れる 3 枚があり、瞬きは元絵の複製にして動かさない。
**組み立ての規則:** 瞬きの絵は口を閉じた全体絵なので、口が開いている間は瞬きを待つ（実装済み）。瞬きの時刻は行の位置で
固定されるので、組み立て直しても同じ瞬きになる。

**配置。**

- ゲーム素材は背景 640×448、立ち絵 320×448（一部 432×448）。1080p の中央に 100 % で置くと小さく浮く。
  **立ち絵は下揃え（`spriteAlign: "bottom"`）、背景と同じ倍率（`spriteScale: 241` = 1080 / 448）** にする。
- 主人公は、自分のルートでは立ち絵が一度も表示されないので台本に出ない。同じ立ち絵はデータにある。
  `protagonist_sprites.py` が、表情の無い主人公に全ての立ち絵を割り当てる。ただし脚色済みの 29 話は
  全ゲームのキャラクター表を持つので、このツールは何も変えなかった（1 ルートだけから切った台本で意味がある）。
- 会話の相手（立ち絵のある側）が、立ち絵のない主人公の行で消えたり出たりする。**直し:** 相手の行に `slot: 3` を付けると、
  他の人が話す間も右に残る。ゲームどおり中央に置きたいときは `rightX: 0.5` で置き場所だけ変えられる。
- 回想 CG の場面に立ち絵が出る。**直し:** 場面に `hideCharacters: true`。

### 3.5 口パクの方式

音量包絡だけで開閉を決める（モデルなし、決定的）。声の大きさを話者自身の大きい部分に対して測り、ヒステリシス
（開いた水準の 3 dB 下まで閉じない）と最短時間 50 ms、絶対下限 −50 dBFS で、静かな部屋で口が開かないようにする。
母音の画像は、読み（`reading`、なければルビ込みの本文）から拍を作り、声が出ている区間に**等間隔**で割り当てる。
音そのものは聞かないので、伸ばした音は短く切られ、漢字ばかりの行は開口のみに落ちる。
**規則:** 漢字の多い行には `reading` を付ける。母音の画像を持つ立ち絵には必ず `openImage` も持たせる。

### 3.6 擬音と効果音

- **何が起きたか。** 効果音の無い擬音の行（物音の文字起こし）を TTS が読むと、棒読みの声になる。
  また、効果音を声のトラックに置くと、声の音量に揃えられて**大きすぎる**（ゲームの効果音は一つひとつが
  最大音量に近く、扉が叫び声と同じ大きさになる）。点だけの行（沈黙の表現）は、合成の対象になって読まれてしまう。
- **直し。** 台本の `spoken: false`: 字幕は出すが声は作らず、口も動かない。音は `sfx`（A3）に置く。行の長さは
  max（効果音の長さ、字数 ÷ `charsPerSecond`、0.8 秒）＋間。`onomatopoeia.py` が、効果音を声として持つ行、効果音キャラの行、
  カタカナだけの擬音などを規則で見つけて印を付ける（第 1 話では 23 行: 効果音ありが 16 行、無音の間が 7 行。
  読み上げのまま残した曖昧な 6 行は見送り）。効果音は声の音量より `effectsBelowVoiceLu`（10 LU）下に揃え、
  上げる量は最大 6 dB、0.4 秒未満の短い音は測れないので `sfxGainDb`（−10 dB）。`anime.check` の `effect-loud` で確かめる。
  点だけの行で録音のないものは `direction`（無音の間）に直す（第 1 話では 26 行）。`episode_plan.py` も、
  点だけの録音なし行を前の行の間に足す（0.6 秒）。
- **規則。** 擬音は読まずに字幕だけ、音は A3 に声より 8 dB 以上（既定 10 LU）小さく。点だけの行は無音の間。
  ゲームの擬音クリップ（`j_擬音` など）は人の声ではなく効果音で、同名の効果音フォルダのファイルと同じ音
  （相関 0.99、AHX 版が 20 ms 遅れ）。

### 3.7 画面と書き出し

- **黒帯。** PS2 の素材は 640×448（4:3 に近い）。1080p の 16:9 に収めると左右に黒帯が出る。決定は**そのままの 4:3**
  （`backgroundFit: "fit"`）。画面いっぱいにする選択肢（`fill`、立ち絵は `spriteScale: 300`）は、背景の上下を
  44 ピクセルずつ切り、立ち絵が背景上で約 130 ピクセル高く立つ。
- **解像度。** PS2 の素材をそのまま拡大して作り、観て問題があればアップスケールを検討する、という決定。
  リニューアル版の素材は手元に無い。
- **書き出し。** 1080p・24 fps・H.264。30 分の話が 11〜13 分（約 60 fps 相当）で書き出せる。
- **間。** ゲームの録音は前後に約 0.28 秒の無音を含むので、`pause` を 0.2 にした（第 1 話の推奨設定）。
  録音のない行は 7 字/秒で長さを見積もる。
- **大きな台本。** 字幕トラックは 1 本入れるたびに並べ替えるので遅い。全話の連結はせず、話ごとに組み立てる。
  1 つの音声が 1 時間を超えるもの、シーケンスが 100 時間を超えるものは使えない。

### 3.8 並列セッションと運用

- **担当ファイルを分ける。** 同じチェックアウトを共有するので、担当以外のファイルは触らない、ブランチを変えない、
  stash・reset をしない。コミットは 1 つのセッションが、タスクごとに**明示的なパス**で行う（1 コミット 1 タスク）。
- **ビルドの衝突を避ける。** Rust を触るセッションは `CARGO_TARGET_DIR=target/agent-<名前>` にする。
- **GPU は 1 本。** 合成は常に 1 プロセス。他の GPU 作業と競合させない。
- **作品を入れない。** `out/` は作品のテキストを含むので `.gitignore`。作品のテキスト・画像・音声、台本の実物、
  合成した音声はリポジトリに入れない。データには読み取りだけで触る。
- **引き継ぎメモ。** 各セッションは共有ノートフォルダに `task-*.md` を残す（できたもの、重要な発見、残り）。
  下流の数字（行数、場面 id、合成のキャッシュ）は、上流（順路）を直すと全部変わる。順路を変えたら下流の作り直しを計上する。
- **品質ゲート。** コミットの前に `cargo xtask ci`（fmt / clippy / test / layers / assets / wasm）と、Python の
  `tools/eve_burst/tests` を通す。
- **機械で判定できる形にする。** LLM に任せる工程（脚色）も、`check_adaptation.py` と `script.validate` の終了コードで
  合否を決める。人が全部読む運用にしない。

## 5. 小説（ゲームでない文字）から作るときの流用

### 流用できるもの

- **台本の形式と `script.validate`。** そのまま使える。`when`・`requires`・`route` は、時系列を入れ替える小説（回想・多視点）で
  使う。
- **合成・口パク・組み立て・検査・書き出しの全部**（`script.synthesize`、`script.lipsync`、`anime.build`、`anime.check`、`anime.run`）。
  台本が同じ形なら、ゲームでも小説でも同じ。
- **声の設計とクローン。** 小説には録音がないので、すべての話者が「設計してからクローン」の対象になる。
  男声の F0 窓、「高め」「しゃがれ」を避ける指示、1 回作って固定、は同じ。声を役名に結び付けて固定する考え（`extras_voices.py`）も流用できる。
- **擬音と効果音の扱い**（`spoken: false`、効果音は声より下、点だけの行は無音の間）。小説の擬音語にも当てはまる。
- **立ち絵の差分の規約**（`_a _i _u _e _o _blink`、同サイズ・同位置）と `sprite_variants.py`、配置の考え（下揃え、背景と同じ倍率、
  `slot`、`hideCharacters`）。
- **話数への切り方と脚色の枠組み**（`episode_plan.py`、`adapt.py`、`check_adaptation.py`）。小説では「録音のある行は削除だけ」の制約が
  なくなるので、**全行を書き換えてよい**。それでも、行 id を保つ、順序を変えない、機械で合否を判定する、は有効。
- **運用**（担当ファイルの分担、GPU 直列、品質ゲート、作品を入れない）。ルビ（青空文庫記法）は話すときの読みと表示の両方に使える。

### 流用できないもの

- **変換器 `eve_to_script.py`、順路の方針、ザッピング、`merge_routes.py`。** ゲームの命令列とフラグを解釈するためのもので、
  小説には分岐がないので要らない（複数視点の小説を日単位で並べたい場合の `when` / `requires` の考えだけは使える）。
- **`assets.py`、素材の名前の対応、`voice_refs.py`、`script.pickVoices`。** 元の録音と、行と録音の対応表があって初めて働く。
  小説では参照音声を自分で用意する（権利と同意に注意）。
- **`mouth_cutouts.py`。** 同じ衣装の別表情が同じ体で描かれていることを前提にしたゲームの立ち絵向け。
  小説では立ち絵そのものを外で作る必要があり、口の差分も外で作って規約に合わせる。
- **ゲーム画面のサイズ（640×448）に由来する倍率（241 %）と黒帯の判断。** 素材のサイズに合わせて決め直す。
- **`game2script.py`** は文字のシナリオ（テキストゲーム）向けで、地の文と台詞が混ざった小説には向かない。

### 小説に固有の、まだ無いもの

- **小説 → 台本の変換（話者推定、地の文のナレーション化、ト書き抽出、場面分割）。** 未着手で、LLM の仕事とされている
  （[novel-to-anime.md](novel-to-anime.md) §1.1、§5）。台本を書き込むコマンド群（`script.*` の書き込み側）も未実装で、
  現状は JSON を直接書く。
- **ルビの付いた長文の読み**（TTS の読みの誤りは小説のほうが目立つ可能性がある。**未確認**）。
- **背景・立ち絵・BGM・効果音の素材。** 画像は生成しない方針なので、外部のツールで用意するか、利用者の素材フォルダを使う。
