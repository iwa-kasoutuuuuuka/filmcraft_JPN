## 0. ゴール

1. **第 1 話を 1 本通す。** 小次郎編の冒頭（ゲーム内 1 日目）を 1080p / 24 fps の mp4 に書き出し、

2. それが通ったら**同じ手順を全話に繰り返す。** 最終形は小次郎編とまりな編を日単位で切り替える
   多視点構成（ゲームのマルチサイトを 1 本の順路にしたもの）。

## 4. 分散のルール（Opus セッション）

- **モデル**: Opus。**同じチェックアウト**（`E:/Zfilmcraft_JPN`）を共有し、**担当ファイル以外は触らない、コミットしない、
  ブランチを変えない**。Rust を触るセッションは `CARGO_TARGET_DIR=target/agent-<name>` でビルドする（ビルドロックの衝突を避ける）。
- 完了報告は「触ったファイル、追加したテスト、実行した検証コマンドとその結果、残した課題」。コミットは利用者が指示する。
- **[AGENTS.md](../AGENTS.md) の規則はそのまま**: クラッシュしない（`unwrap` 禁止、入力は敵対的）、クリーンルーム、ピュア Rust、
  時間は Tick。Python の道具は標準ライブラリのみ、ダンプは読み取り専用、素材はリポジトリに入れない。
- 台本（D）の作業は**コードではなく内容**。セッションには台本ファイルと [script.md](script.md) の format と「行の `text` を変えない」
  規則だけ渡す。
- GPU 作業（E）は常に 1 本。`script.synthesize` はキャッシュがあるので、途中で止めても次回は続きから。

## 6. 決定（2026-11-06、利用者）

1. **圧縮率**: 1 話 **24〜30 分**（脚色 D の目標は 550〜700 行）。全体は **28〜30 話**、最終話は 1 時間程度でよい。
   **録音の無い行（主人公の台詞の大半）は、筋に影響しない範囲で書き換え・統合してよい**（録音のある行は削除のみ）。
   → `episode_plan.py` で 29 話（27 分 × 28 話＋最終話 60 分、全体で約 39% を残す）の下書きを作り、
   `check_adaptation.py` で検査する（[eve-burst-convert.md](eve-burst-convert.md)「A series of episodes」）。
2. **男性エキストラの声**（2-7）: **他の TTS / 声の設計で男性の声を用意できるか検討する** → 検討済み。Qwen3-TTS の VoiceDesign で設計してクローンする（§7）。脇役の声を借りるのは次善。
3. **解像度**（2-8）: **PS2 素材をそのまま拡大してサンプルを作る**。観て問題があればアップスケールを検討。
4. **順路**（2-3）: **原作を尊重した多視点構成**。第 1 話から小次郎編とまりな編を日単位で交互にする。
   → D（脚色）は A の `merge_routes.py` の出力（両編を交互にした順路）を入力にする。第 1 話 = 1 日目の両視点。

## 6.1 全話展開の進め方（2026-11-09 決定）

- **声の演技**: Qwen3-TTS に感情別の参照クリップを行ごとに渡す B1 で全話に展開する（`docs/eve-burst-tts-quality.md` §10）。

## 7. 男性エキストラの声（決定 2 の検討）

日本語の男性プリセットは Qwen3-TTS の CustomVoice に無い（`Ono_Anna` のみ）。選択肢:

| 方法 | 仕組み | 利点 | 欠点 |
|---|---|---|---|
| **Qwen3-TTS VoiceDesign → クローン**（推奨） | 同じ Qwen3-TTS の VoiceDesign モデル（Apache-2.0）に「40代の男性警備員、低く落ち着いた声」と文章で指示して 1 文を作り、その WAV を参照クリップにして Base モデルでクローンする（公式 README の "design, then clone"） | 道具が増えない（`filmcraft_tts.py` の `design` 1 項目）。台本側は `refAudio` / `refText` のままで Rust 側の変更なし。役ごとに別の声を無限に作れる。実在の人の声を使わない | 設計のたびに声が少し変わるので「1 回作ってクローン」が必須。日本語の男性の自然さは聴いて判断（§7.1） |
| 脇役の声を借りる | `hon` / `kat` / `dep` の別クリップを参照にする | 作品の声優の声で統一感がある | 同じ声が別の役で出る。参照にした声優の声を役者の意図しない役に使う |
| 他の TTS（VOICEVOX / Style-Bert-VITS2 / Kokoro 等） | 同じ JSON Lines プロトコルを話す別スクリプトを `script` パラメータで指す | VOICEVOX は日本語男性の声が多数あり無料 | エンジンが LGPL（外部プロセスとしては ffmpeg と同じ扱いで可だが、同梱不可）。キャラクターごとの利用規約（クレジット表記など）。声の質が Qwen3-TTS と揃わず、`anime.check` の `loudness` 警告が増える。未検証 |

### 7.1 検証

`filmcraft_tts.py` に `design`（ジョブの項目と `--design`）を足し、RTX 5080 で試した（VoiceDesign モデルの初回ロードは
ダウンロード込みで 122 s、以後の 1 文は数秒）。聴く前の客観値として基本周波数（F0、男声の目安 85〜160 Hz、女声 165〜255 Hz）を
自己相関で測った。比較: 女性プリセット `Ono_Anna` は 271 Hz、そのクローンは 245 Hz。

| 指示文 | 結果 | F0 中央値 | 判定 |
|---|---|---:|---|
| 40代の男性警備員、低めで落ち着いた声、ゆっくり、事務的 | `guard-ref.wav` 8.8 s | 86 Hz | **男声**。同じ指示でもう 1 文作ると 86 Hz、それを参照にクローンした 2 行は 85 / 87 Hz（声が保たれる） |
| 30代の男性のフロント係、明るく丁寧、やや高めの声 | `front-ref.wav` 4.2 s | 211 Hz | 女声域。「やや高め」が効きすぎる |
| 50代の男性警官、太くしゃがれた低い声、威圧的で早口 | `police-ref.wav` 7.0 s | 235 Hz（94〜308 と不安定） | 要注意。クローン後は 273 Hz で女声域 |

結論（推奨）: **VoiceDesign で参照を 1 文作り、Base でクローンする。** 指示文は「低い声の男性」を明示し、「高め」「しゃがれ」
などの修飾は避ける。設計は当たり外れがあるので、役ごとに 2〜3 回作って F0 が 160 Hz 未満のものを採用し、必ず聴いて決める。
採用した参照 WAV と文章を `voice_refs.json` と同じ形で `extras_refs.json` に保存し、`apply_voices.py` の対象にする
（台本側は `refAudio` / `refText` のままなので Rust の変更は不要）。サンプルはスクラッチパッドの
作業用の一時フォルダ（リポジトリ外）。
